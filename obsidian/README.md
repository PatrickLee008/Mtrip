# mTrip 共享知识库

知识库目录：`obsidian/mTrip_obsidian/`，与项目代码一起通过 Git 共享。

## 打开与阅读

1. 取得包含此目录的项目版本；后续通过项目原有 Git 流程获取更新。
2. 安装 Obsidian 后，选择“打开文件夹作为仓库”，打开本项目中的 `obsidian/mTrip_obsidian/`。
3. 从 `00-mTrip 产品知识库.md` 进入对应产品和业务模块。不要在知识库内再创建一层 `mTrip_obsidian`。

无需社区插件、Obsidian Sync、环境变量或额外服务。未安装 Obsidian 时也可用编辑器直接阅读 Markdown 和原始 PRD 快照；笔记间的 `[[...]]` 链接由 Obsidian 提供导航。

## 内容与版本

| 产品 | 导入快照版本 |
| --- | --- |
| 消费者 App | v1.0.6 中文版 |
| 商户 App | v1.0.12 中文版 |
| 超级管理后台 | Enterprise v1.0.11 中文版 |

这些是导入快照，不代表所有功能均已实现，也不自动替代任务已确认的 PRD 基线。各产品的 `08-原始资料/` 保留原始快照与附件，`09-导入记录/` 保留导入记录；历史记录中的原机器路径仅用于溯源，无需在其他成员机器上存在。

## 协作方式

- 笔记、原始快照、附件和导入记录随项目 Git 提交、评审与更新，不另建嵌套 Git 仓库。
- `.obsidian/` 个人配置和 `.trash/` 回收站由项目忽略规则排除，原有本机配置予以保留；其他成员首次打开时由 Obsidian 生成本机配置。
- 普通开发任务读取知识库；PRD 或知识库变更作为明确任务处理，保留原始来源和人工整理内容。
- 知识库缺失或不可读时按项目需求资料继续，不阻塞开发、构建、测试或提交。

详细工作规范见[知识库关联开发规范](../docs/guides/standards/知识库关联开发规范.md)。
