# 技术考量与跨平台集成

##### 技术考量

- 认证服务
- 在超级管理后台与商户 App 认证服务之间，同步每个商户的登录方式状态。
- 支持由已授权的管理员发起的即时会话撤销、待处理的二维码登录失效，以及可信设备/生物识别信任撤销。
- 返回通用的认证错误，并在管理视图中对关联的电子邮件地址和手机号码进行掩码处理，除非某个被允许的支持工作流需要更多细节。
- 商户 App 集成
- 消费者 App 集成
- 通知服务
- 分析服务
- 未来支付服务
- 审计日志
- PMS 集成服务
- Channel Manager 集成服务
- API 网关
- 配置管理服务
- 文件存储服务（商户文档）
- 监控与告警
- 集成日志
- 数据备份与恢复

将受支持的 mTrip 客户端应用程序与集中的指南中心服务/API 集成，以交付指南内容。超级管理后台不属于指南中心内容管理工作流的一部分。

指南创建、元数据/配置、定向、排序、发布和维护，由已授权的运营用户在指南中心直接处理。

技术团队可以使用模块 21 下列出的指南中心环境、API 文档、用户指南和开发者指南，进行集成测试与验证。

客户端集成应遵循指南中心 API 所支持、并经工程团队约定的认证/授权、检索、错误处理、重试、监控及其他技术要求。

**餐厅数据核验与覆盖**

在第三方餐厅源数据（例如 Google Place ID/源属性）与 mTrip 自有的核验状态、人工更正和上架可见性覆盖之间，保持清晰的分离。

面向消费者的餐厅检索应应用有效的 mTrip 上架状态/覆盖，而不修改原始的第三方源记录。

所有人工核验与覆盖操作必须进行权限控制，并以旧值/新值、原因、管理员和时间戳记录到审计日志。
