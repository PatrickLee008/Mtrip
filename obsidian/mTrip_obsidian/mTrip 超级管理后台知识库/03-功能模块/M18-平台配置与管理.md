### 模块 18：平台配置与管理

##### 目标

使超级管理员能够配置并维护平台级设置、业务规则、集成与基础数据，以确保 mTrip 生态系统中平台运营、安全性与可扩展性的统一一致。

##### 描述

平台配置与管理设置模块使超级管理员能够管理影响整个 mTrip 平台的全局配置。这包括通知模板、平台设置、基础数据、集成、平台服务、本地化设置以及维护配置。这些设置确保商户 App、消费者 App 与超级管理后台之间行为的一致性。

##### 功能需求

##### 平台设置

- 配置平台设置。
- 配置本地化设置，包括支持的语言、货币与时区。
- 管理系统维护模式与系统可用性。
- 管理平台公告。

##### 通知管理

- 管理通知模板。
- 配置邮件、短信、推送通知及 App 内通知模板。

##### 商户配置

- 配置商户入驻要求。
- 管理所需的商户文件模板。
- 创建、编辑、启用与停用支持的商户类别。
- 配置平台业务规则。
- 启用或停用平台功能。

##### 业务配置

- 配置佣金设置。
- 配置取消政策模板。
- 配置退款政策模板。
- 配置结算参数。

**酒店预订配置**

- 配置多酒店预订的最大连住次数。该值定义了客户在单笔多酒店预订中可添加的独立酒店住宿的最大数量。

示例：如果最大连住次数配置为 3，客户在单次支付结算中最多可添加 3 次住宿。一旦达到配置的上限，消费者 App 应隐藏或禁用“添加更多住宿”操作。

- 如果客户移除一个或多个先前添加的住宿，且总数低于配置的最大值，“添加更多住宿”操作应重新可用。
- 配置的上限应由后端强制执行，并在消费者 App 中一致体现。

##### 集成配置

- 配置 PMS 集成设置。
- 配置 Channel Manager 集成设置。
- 管理第三方 API 连接。
- 配置 API 凭证与连接状态。

##### 基于位置的服务（LBS）

- 配置地图服务提供商。
- 配置默认搜索半径与距离计算。
- 管理地理围栏与服务覆盖范围。
- 配置平台在位置权限与附近搜索方面的行为。
- 监控位置服务状态与 API 连接状态。

##### 业务规则

- 仅授权管理员可依据其分配的角色与权限修改平台配置设置。
- 配置变更依据平台业务规则生效。
- 所有配置变更必须记录于审计日志中。
- 维护模式仅可由授权用户启用或停用。
- 本地化设置在各支持平台间一致应用。
- 通知模板的变更仅影响后续通知，不会修改此前已发送的通知。
- 集成设置仅可由授权管理员修改。
- 配置变更不得影响已完成交易。
- 功能配置变更依据所配置的启用规则生效。
- 对商户入驻要求的变更仅适用于新申请，除非另有说明。
- 位置配置变更仅适用于后续基于位置的服务，除非另有说明。
- 配置变更在应用到平台前必须经过验证。
- 最大连住次数必须为正整数，并依据当前生效的平台配置，适用于新建及进行中的多酒店预订。
- 当预订已达到配置的最大连住次数时，即使绕过消费者 App 的控制，后端也应拒绝任何添加住宿的请求。

##### 验收标准

- 超级管理员可创建、编辑并管理通知模板。
- 超级管理员可配置平台设置。
- 超级管理员可创建、编辑、启用与停用类别。
- 超级管理员可配置支持的语言、货币与时区。
- 超级管理员可启用或停用维护模式。
- 未授权用户无法修改平台配置或系统设置。
- 所有配置变更均记录于审计日志中。
- 超级管理员可配置 PMS 集成设置。
- 超级管理员可配置 Channel Manager 集成设置。
- 超级管理员可管理商户入驻要求。
- 超级管理员可配置业务规则参数。
- 超级管理员可启用或停用平台功能。
- 超级管理员可配置基于位置的服务（LBS）设置。
- 超级管理员可配置并更新多酒店预订的最大连住次数。
- 当达到配置的最大连住次数时，消费者 App 会禁用或隐藏“添加更多住宿”操作，并阻止添加额外住宿。
- 当移除住宿且住宿总数低于配置的最大值时，“添加更多住宿”操作重新可用。
- 后端校验可防止多酒店预订超过配置的最大连住次数。
