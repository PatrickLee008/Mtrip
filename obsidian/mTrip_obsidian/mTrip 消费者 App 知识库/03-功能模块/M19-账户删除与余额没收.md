## 模块 19：附加功能：mTrip 账户注销

![](../08-原始资料/images_consumer/img_023.png)

**1. 入口**

更多 → 账户（设置、安全、支付）→ 管理你的账户 → 账户注销

#### 2. 账户注销流程

- 用户查看账户注销警示并点击“继续”。
- 用户输入 DELETE（区分大小写）。
- 用户点击“确认账户注销”。
- 系统检查：
    - 存在进行中/待处理的预订
    - mTrip 钱包余额 > 0
- 若满足任一条件 → 阻止注销，用户可点击“联系客服”。
- 若均不满足 → 账户注销成功。
- 系统自动退出登录，并跳转至登录/注册页。

![](../08-原始资料/images_consumer/img_024.png)

**mTrip 账户注销 UI 界面流程**

**3. 取消**

用户可点击“取消并保留我的账户”中止流程。账户保持有效状态，不执行注销。

**4. 数据保留**

注销成功后，相关账户数据将按 mTrip 的数据保留政策保留 90 天。

**5. mTrip 钱包余额**

若用户在 mTrip 钱包余额大于 0 时申请账户注销，该余额将作废，且在账户注销后无法退还、转移或找回，并须符合适用条款与法律。

**6. 新账户**

账户注销后，用户可创建一个新的 mTrip 账户。新账户按新账户处理，不会自动恢复已注销账户的数据、钱包余额或权益。

**7. 业务规则**

| 条件 | 结果 |
|---|---|
| 存在“待支付”预订 | 阻止注销 |
| 存在“已确认”预订且退房日期尚未过去 | 阻止注销 |
| 存在“已入住”预订 | 阻止注销 |
| 存在“退款处理中”（无论预订状态如何） | 阻止注销 |
| mTrip 钱包余额超过超级管理员配置的最低余额阈值 | 阻止注销；用户须联系客服寻求协助 |
| 客服/获授权的超级管理员在钱包仍有余额的情况下批准注销 | 余额作废 → 允许注销 |
| 存在“已确认”预订但退房日期已过 | 允许注销 |
| 存在“已退房/已取消”预订且所有相关支付/财务流程已完成 | 允许注销 |
| 存在“未入住（No-Show）”预订且所有相关支付/财务流程已完成 | 允许注销 |
| 无阻断性预订，且 mTrip 钱包余额等于或低于超级管理员配置的最低余额阈值 | 允许注销 |
| 注销成功 | 退出登录 → 登录/注册页 |

**附加业务规则：**

- 预订资格必须依据预订状态与计划退房日期判定。
- “已确认”预订的退房日期已过时，即使商户未将状态更新为“已退房”或“未入住（No-Show）”，也不得阻止账户注销。
- 系统不得仅为便于账户注销而自动变更预订状态。
- 任何处于“退款处理中”的预订必须持续阻止注销，直至退款流程完成。
- 历史预订记录必须按适用的数据保留政策保留。
- 最低钱包余额阈值必须可由超级管理员配置。
- 账户注销资格必须通过将用户当前 mTrip 钱包余额与配置的最低余额阈值进行比较来判定。
- 若钱包余额等于或低于配置阈值，用户可直接进行账户注销，无需额外审批。
- 若钱包余额超过配置阈值，默认必须阻止账户注销，用户须联系客服寻求协助。
- 客服可对符合条件的案例提交钱包余额作废审批请求，须经超级管理员制单-复核（maker-checker）审批流程。
- 不得仅因钱包余额等于或低于配置阈值而自动将其作废。

#### 示例：最低钱包余额阈值

假设：超级管理员将最低钱包余额阈值配置为 500 MMK。

| 用户钱包余额 | 配置阈值 | 账户注销 |
|---|---|---|
| 0 MMK | 500 MMK | 允许 |
| 100 MMK | 500 MMK | 允许 |
| 500 MMK | 500 MMK | 允许 |
| 501 MMK | 500 MMK | 阻止 |
| 1,000 MMK | 500 MMK | 阻止 |

**mTrip 钱包余额阈值补充说明**

- 该阈值可由超级管理员配置。
- 钱包余额等于或低于阈值的，可直接进行账户注销，无需额外审批。
- 钱包余额超过阈值的，须由客服协助，并经授权的钱包余额作废审批。
- 系统必须在用户提交账户注销申请时检查最新的钱包余额。

**8. 钱包余额与欺诈防范**

若用户的 mTrip 钱包余额大于 0，必须阻止账户注销。

用户须联系客服进行核实与后续处理。

若客服/管理员批准账户注销，剩余钱包余额将作废，并记入内部“已作废 mTrip 钱包余额台账”，用于会计与审计。

已作废的余额不得由用户转移、退还、找回或使用。
