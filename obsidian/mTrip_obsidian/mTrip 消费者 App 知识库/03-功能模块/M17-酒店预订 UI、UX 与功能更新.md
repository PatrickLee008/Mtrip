## 模块 17 – 酒店预订 UI、UX 与功能更新（2026 年 9 月 4 日）

本模块记录在上一版 PRD / 设计基线之后，针对酒店预订功能所做的主要界面、交互、功能和流程变更。最新已批准的 Figma 设计以及本 PRD 中更新后的需求，应作为开发和测试（QA）的当前唯一事实来源。

**酒店预订 UI 与功能更新变更记录**

| 序号 | 模块 / 功能 | 变更说明 | 更新的流程 / 行为 | 状态 |
|---|---|---|---|---|
| 1 | 酒店预订状态 | 更新“酒店预订状态”页面，将酒店预订状态与支付状态清晰分离。（查看更新后的界面） | 酒店预订状态：确认中 → 已确认 / 支付状态：待支付 → 已支付 | 已更新 |
| 2 | 注册 / 登录 | 在初始注册入口页面用姓名输入框替换邮箱输入框。更新了“注册 / 登录”按钮的设计和行动号召（CTA）呈现。 | 注册入口 → 更新后的身份验证界面输入（移除邮箱，新增姓名输入） | 已更新 |
| 3 | 初始 App 加载 — 语言选择 | 在初始 App 加载 / 入口流程中新增专用的语言选择页面。 | App 加载 → 语言选择 → 轻量模式 / 完整模式选择 | 新增 |
| 4 | 初始 App 加载 — 轻量 / 完整模式 | 将轻量模式设为语言选择后的默认体验，不再展示初始的轻量模式 / 完整模式选择弹窗。 | App 加载 → 语言选择 → App 首页 → 轻量模式 | 新增 |
| 5 | 预订编号 | 在关键预订相关页面新增唯一预订编号，便于识别和查询预订。预订编号：MT-2025-123456 | 预订确认 → 预订详情 → 预订历史 / 已完成预订 → 展示预订编号 | 已更新 |
| 6 | 全局卡片 / 矩形圆角 | 统一酒店功能及 App 功能中卡片 / 矩形界面组件的圆角。圆角更新为 24px，以保持全 App 视觉风格一致。 | 原圆角 → 统一的 24px 圆角 | 已更新 |
| 7 | 退款方式页面 | 更新“退款摘要”下退款方式卡片和预计退款时间卡片（含标题与正文）的排版，以提升可读性和视觉一致性。 | 原排版 → 更新后的标题 / 正文排版（调整了标题与正文字号） | 已更新 |
| 8 | 预订确认 — 轻量模式与完整模式 | 更新轻量模式和完整模式下的预订确认页面，与最新预订信息和 UX 设计保持一致。 | 预订完成 → 更新后的预订确认页面 | 已更新 |
| 9 | 确认页取消预订 | 从预订确认页面移除“取消预订”按钮。用户现在只能从该页面查看预订详情；修改或取消需在我的精选中操作。 | 预订确认 → 查看详情 → 我的精选 / 预订详情 → 修改预订 / 取消预订 | 已更新 |
| 10 | 需要登录账号提示 | 更新了用户未登录却尝试使用酒店预订功能时展示的账号提示的标题和内容。 | 标题：需要登录账号！内容：是否立即前往登录 / 注册页面？确认 → 注册 / 登录页面 | 已更新 |
| 11 | 设置个人资料 — 第 1 步与第 2 步 | 移除“设置个人资料”第 1 步和第 2 步中的“跳过”按钮。新增确认弹窗，允许用户立即完成设置或稍后完成。 | 设置个人资料 → 是否立即设置个人资料？ → 稍后 / 立即设置 | 已更新 |
| 12 | 设置个人资料提示 | 新增个人资料设置提示，内容如下：标题：是否立即设置个人资料？内容：只需填写一次信息，以后的预订将更快捷、更轻松。按钮：稍后 / 立即设置 | — 稍后 → 跳过第 1 步和第 2 步；— 立即设置 → 完成第 1 步 → 完成第 2 步 | 新增 |
| 13 | 关联邮箱 — 账号安全 | 在“设置 → 账号 → 账号安全”下新增“关联邮箱”页面。未关联邮箱的用户将看到“关联邮箱”选项。 | 设置 → 账号 → 账号安全 → 关联邮箱 → 输入邮箱 → 发送验证码 | 新增 |
| 14 | 关联邮箱 — 验证 | 新增邮箱关联页面，用户可输入邮箱地址并接收验证码。 | 关联邮箱 → 输入邮箱 → 发送验证码 → 邮箱验证 | 新增 |
| 15 | 酒店评价 — 有用 / 举报 | 从酒店用户评价列表页面移除“有用”（点赞）反应按钮和“举报评价”图标。 | 原评价操作 → 仅评价内容 | 已更新 |
| 16 | 多酒店预订 — 添加更多住宿 | 更新多酒店预订体验，新增可展开 / 收起的“添加更多住宿”卡片，使更多住宿的管理更加便捷。多段住宿上限：用户可添加的最大住宿数量由后台管理端配置控制。例如，若最大住宿数量配置为 3 段，则用户在一次预订中最多可添加 3 段住宿。达到上限后，“添加更多住宿”按钮将被隐藏或禁用；当用户移除一段或多段已添加的住宿后，“添加更多住宿”选项将重新可用。 | 酒店预订 → 添加更多住宿 → 展开 / 收起 → 添加额外住宿。用户可根据后台管理端配置的最大住宿数量添加多段住宿。达到配置上限后，“添加更多住宿”按钮将被隐藏 / 禁用。若用户移除已添加的住宿，该按钮将重新可用，直至再次达到上限。 | 已更新 |
| 17 | 多酒店预订 — 轻量模式限制 | 在轻量模式下禁用 / 移除多酒店预订功能。该功能仅在完整模式下可用。 | 轻量模式 → 仅支持单酒店预订 / 完整模式 → 支持多酒店预订 | 已更新 |
| 18 | 服务条款 / 隐私政策 / 房屋规则协议 | 更新“复核并确认”步骤中展示的协议内容，移除了原有的复选框 / 确认交互。隐私政策、条款与条件和优惠券促销中心页面必须在 mTrip App 内以网页嵌入链接方式实现，以确保 App 始终展示并与 mTrip 网站发布的最新版本同步。 | 第 3 步（共 4 步）：复核并确认 → 展示协议文本 → 继续 / 确认 | 已更新 |
| 19 | 预订协议内容 | 更新协议文本，清晰传达用户的接受行为及 mTrip 的中介角色。 | “继续即表示我同意服务条款、隐私政策和该门店的房屋规则。我了解 mTrip 作为本次预订的中介代理。” | 已更新 |
| 20 | 协议交互 | 用户不再需要手动勾选复选框或通过额外弹窗确认协议。协议以说明性文本形式展示在“复核并确认”步骤。 | 复核并确认 → 阅读协议 → 继续 / 确认（已移除复选框） | 已更新 |
| 21 | 选择客房（相同或不同房型） | 原：用户只能预订一间客房。更新：用户现在可以选择并预订多间客房，房型可以相同或不同。 | 选择客房 → 选择多间客房（相同或不同房型） | 已更新 |
