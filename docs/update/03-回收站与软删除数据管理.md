# 专项升级 03:回收站与软删除数据管理

> 日期:2026-07 | 状态:已开发完成 | 影响范围:backend/services/system-service、admin-web、database/seed

## 1. 背景与目标

- 平台各表普遍采用软删除(`deleted_at`)。带唯一键的表(如 `user_info.uk_site_mobile_hash`、`sys_admin` 用户名)一旦软删,同名/同标识数据便**无法重新创建**——唯一索引仍占用,而记录对业务不可见。
- 此前没有任何入口查看或处理已软删数据,只能手动进库操作,既不安全也不可审计。
- 目标:新增一个「回收站」,统一集中管理两库全部配置/基础数据表的软删记录,支持**恢复**、**彻底删除单条**、**一键清空**。唯一性规则完全不改,只增加对已删数据的处理入口。

## 2. 总体设计

### 2.1 集中式架构

全库仅 `mtrip_system` 与 `mtrip_business` 两库,共用同一 MySQL,`mtrip` 账号对两库均有全部权限。因此采用**集中式**:在 `system-service` 内增加一个 `business` 连接,即可用一个注册表驱动的控制器覆盖两库全部目标表——一个后台页面、一套 API 搞定,新增/移除可回收表只改一处注册表数组。

### 2.2 注册表(单一事实源)

`app/Support/RecycleRegistry.php` 为静态数组,每项:`key`(白名单键=表名)、`conn`(system/business)、`table`、`group`(分组展示)、`label`/`labelEn`(内置中英文名,不污染前端 locale)、`scope`(site/global)、`title`(列表展示的名称字段,不含任何敏感/加密列)、`search`(关键词 LIKE 字段)。

**数据范围**:仅纳入配置/基础数据表(均含 `site_id`),**排除**交易/财务流水/审计/高频库存等表(`order_main`、`order_refund`、`finance_merchant_settle`、`finance_withdraw`、`supplier_settle`、`marketing_coupon_receive`、`marketing_activity_goods`、`goods_daily_stock`、`sys_file`、`user_feedback`)。

| 分组 | 连接 | 表 |
| --- | --- | --- |
| 系统(system) | system | `sys_admin`、`sys_role`、`sys_menu`*、`sys_config`*、`sys_site`*、`sys_site_config`、`sys_storage`、`sys_pay_channel`、`sys_sms_channel`、`sys_sms_template`、`sys_map_config`、`sys_client_perm_template`、`sys_client` |
| 业务(business) | business | `user_info`、`user_member_level`、`merchant_info`、`merchant_account`、`merchant_admin`、`supplier_info`、`supplier_goods`、`goods_category`、`goods_info`、`hotel_room_type`、`ticket_type`、`goods_refund_rule`、`verify_device`、`verify_rule`、`marketing_coupon`、`marketing_activity`、`marketing_banner`、`marketing_points_rule`、`finance_tax_config` |

> 标 `*` 者 `scope=global`(仅超管可见,无 `site_id` 列);其余 `scope=site`(站点管理员按 `site_id` 隔离,超管全量)。

### 2.3 安全约束

- 所有查询/操作**只针对 `whereNotNull('deleted_at')` 的行**,绝不触碰在用数据。
- 表名只能来自注册表(白名单),杜绝任意表注入;非法 `key` 直接 `40001`。
- `scope=site` 且非超管时强制 `where site_id = 当前站点`;`scope=global` 且非超管直接抛 `40302 无数据权限`。
- 写操作(restore/purge/empty)带 `#[Permission]` 注解,经现有 `OperationLogMiddleware`(module=`sys`)自动审计。

## 7. 注意事项

- **唯一键恢复冲突**:恢复会命中唯一索引(如同名数据已重建),接口捕获 `Duplicate entry` 转 `40901` 友好提示,不会 500。需先彻底删除占用项再恢复。
- **站点隔离**:`scope=site` 表对非超管强制按 `site_id` 过滤;`scope=global` 表(`sys_menu`/`sys_config`/`sys_site`)仅超管可见。
- **彻底删除不可逆**:purge/empty 为物理删除,数据无法找回;empty 必须带 `confirm=1` 且前端有二次确认。
- 敏感/加密列永不出现在列表返回中(注册表 `title`/`search` 已排除)。
- `tables()` 对约 32 张表各做一次 COUNT,后台低频访问,性能可接受。
