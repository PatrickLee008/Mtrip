# Mtrip 本地启动开发指南

> 适用于开发环境从零启动全栈(后端微服务 + 管理后台 + 移动端)。
> 容器化一键启动已落地(见第2节);网关路由/限流细节见 `docs/plans/08-部署与网关.md`。
> 更新时间:2026-07-28

## 1. 环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| PHP | >= 8.1 + Swoole 5.x | Hyperf 3.1 运行时;**Swoole 不支持 Windows 原生**,Windows 下请用 Docker 或 WSL2 |
| Composer | 2.x | 后端依赖管理 |
| MySQL | 8.0 | 双库:`mtrip_system` / `mtrip_business` |
| Redis | 6+ | 缓存/登录失败锁定 |
| Node.js | >= 18 | admin-web(Vite5)与 client-app(Expo 51) |

## 2. 一键启动:Docker Compose(推荐)

需 Docker Desktop(Windows 下含 WSL2 后端)或任意 Docker 20+ 环境;Windows 首次安装见 2.0 节。

### 2.0 前置:Windows 安装 Docker Desktop 与配置 WSL2

适用于首次搭环境,或 Docker Desktop 启动报「未检测到虚拟环境」/ WSL 报 HCS_E_SERVICE_NOT_AVAILABLE 时。

**第 1 步:确认 CPU 虚拟化已开启(BIOS 层)**

```powershell
Get-CimInstance Win32_Processor | Select-Object VirtualizationFirmwareEnabled
```

- `True`:跳过本步,不用进 BIOS;
- `False`:重启进 BIOS 开启虚拟化(Intel 叫 VT-x,AMD 叫 SVM,一般在 Advanced/CPU Configuration 下)。

**第 2 步:启用「虚拟机平台」与 WSL 功能**(不需要勾完整的 Hyper-V)

管理员 PowerShell 一条命令(推荐):

```powershell
wsl.exe --install --no-distribution
```

或控制面板 → 程序 → 启用或关闭 Windows 功能,勾选「**虚拟机平台**」与「**适用于 Linux 的 Windows 子系统**」。

**第 3 步:重启电脑**(必须),然后验证 WSL2 就绪:

```powershell
wsl --update          # 更新 WSL 内核
wsl --status          # 不再提示「请启用虚拟机平台」即正常
```

**第 4 步:安装/启动 Docker Desktop**

- 官网下载安装(https://www.docker.com/products/docker-desktop/),安装时选 WSL2 后端;
- 启动后 Settings → General 确认勾选 **Use the WSL 2 based engine**;
- 验证:`docker run --rm hello-world` 能输出 Hello from Docker! 即就绪。

常用诊断命令:

| 命令 | 看什么 |
| --- | --- |
| `Get-CimInstance Win32_Processor \| Select VirtualizationFirmwareEnabled` | BIOS 虚拟化是否开启 |
| `Get-CimInstance Win32_ComputerSystem \| Select HypervisorPresent` | Windows 虚拟机监控程序是否在跑(重启启用功能后应为 True) |
| `wsl --status` / `wsl --version` | WSL 默认版本、内核版本、缺什么组件会直接提示 |

### 2.1 启动全栈

```bash
cd deploy
cp .env.example .env        # 可直接用默认值;生产必须换 JWT/AES 强随机值
docker compose up -d --build
```

- 启动后:网关 `http://localhost:8080`、MySQL 宿主机 `3307`、Redis `6380`;首次启动 MySQL 自动执行 database/ 全部 18 个 SQL(建库+DDL+种子)。
- 前端照常本机 `npm run dev`(admin-web 代理已指网关 8080;client-app 默认即 8080)。
- 验证:`curl -X POST http://localhost:8080/api/v1/admin/auth/login` 返回 `{code,message,data}` JSON(无参报参数错误属正常)即网关→system-service 链路通。
- 仅重建单个服务:`docker compose up -d --build goods-service`;重初始化数据库:`docker compose down -v` 后重新 up。

### 2.2 改代码后如何生效(重要)

Hyperf 是常驻内存模式(非 PHP-FPM),代码启动时一次性加载进内存,**改代码必须重启服务进程才生效**。
开发期已配备 `deploy/docker-compose.override.yml`(compose 自动合并,把本地 `app/`、`config/`、`shared/src/` 挂载进容器覆盖镜像内代码):

| 改动内容 | 生效方式 | 耗时 |
| --- | --- | --- |
| 业务代码(app/、config/、shared/src/) | `docker compose restart xxx-service` | 约 2 秒 |
| composer.json 新增依赖 / Dockerfile | `docker compose up -d --build xxx-service` | 重建镜像 |
| 数据库 DDL/种子 SQL | 已启动过的库不会重跑 init SQL,手动进 3307 执行;或 `down -v` 重建 | — |
| 网关配置(openresty/) | 已挂载,`docker compose restart gateway` | 秒级 |

日志与配置的查看位置(均在宿主机,无需进容器):

- 业务日志:`deploy/logs/<服务名>/hyperf-<日期>.log`(override 已挂出 runtime/logs,按天滚动保留 14 份,已 gitignore);
- 启动/崩溃等进程级输出:`docker compose logs -f xxx-service`(未落盘部分看这里);
- 服务配置:直接改本地 `backend/services/xxx/config/`(已挂载进容器),改完 restart 生效;环境变量类配置改 `deploy/.env` 后 `docker compose up -d` 重建容器生效。

生产部署不走 override:`docker compose -f docker-compose.yml up -d --build` 显式指定即跳过合并。

以下第 3~4 节为**不用 Docker 时**的手动启动方式(需自备 Linux/WSL2 的 PHP+Swoole 环境)。

## 3. 数据库初始化(手动方式)

按顺序执行 `database/` 下 SQL(root 或有建库权限账号):

```bash
mysql -uroot -p < database/init/00-create-databases.sql   # 建库 + mtrip 账号
mysql -uroot -p mtrip_system  < database/system/01-admin-role-menu.sql
mysql -uroot -p mtrip_system  < database/system/02-log.sql
mysql -uroot -p mtrip_system  < database/system/03-config-site.sql
mysql -uroot -p mtrip_system  < database/system/04-storage-file.sql
mysql -uroot -p mtrip_system  < database/system/05-pay-sms-map.sql
mysql -uroot -p mtrip_system  < database/system/06-client.sql
mysql -uroot -p mtrip_business < database/user/01-user.sql
mysql -uroot -p mtrip_business < database/merchant/01-merchant.sql
mysql -uroot -p mtrip_business < database/merchant/02-supplier.sql
mysql -uroot -p mtrip_business < database/goods/01-goods.sql
mysql -uroot -p mtrip_business < database/order/01-order.sql
mysql -uroot -p mtrip_business < database/order/02-verify.sql
mysql -uroot -p mtrip_business < database/finance/01-finance.sql
mysql -uroot -p mtrip_business < database/marketing/01-marketing.sql
# 种子数据(默认管理员/菜单/站点配置)
mysql -uroot -p mtrip_system < database/seed/01-admin-role.sql
mysql -uroot -p mtrip_system < database/seed/02-menu.sql
mysql -uroot -p mtrip_system < database/seed/03-config-site.sql
```

默认业务账号:`mtrip / mtrip@2026`(见 `00-create-databases.sql`,与各服务 `.env.example` 一致)。

## 4. 后端微服务(backend/services/*,手动方式)

各服务结构相同,以 system-service 为例(其余同理替换目录):

```bash
cd backend/services/system-service
cp .env.example .env          # 按本机修改 DB/Redis 连接
composer install              # shared 包为 path 仓库自动 symlink,无需单独安装
php bin/hyperf.php start
```

| 服务 | 端口 | 依赖库 |
| --- | --- | --- |
| system-service | 9501 | mtrip_system |
| user-service | 9502 | mtrip_business |
| goods-service | 9503 | mtrip_business |
| order-service | 9504 | mtrip_business |
| merchant-service | 9505 | mtrip_business |
| finance-service | 9506 | mtrip_business |
| marketing-service | 9507 | mtrip_business |
| payment-service | 9508 | mtrip_business(仅渠道抽象+回调,无管理端路由) |

- 健康检查:`GET http://127.0.0.1:{port}/healthz`
- `.env` 关键项:`MTRIP_JWT_SECRET` / `MTRIP_AES_KEY` 各服务**必须一致**(跨服务验签/解密),生产必须更换强随机值
- 改代码后重启即可(开发环境 `SCAN_CACHEABLE=false` 不缓存注解扫描);Docker 方式见上文 2.2 节
- 仅做语法检查:`php -l <file>`;shared 纯逻辑单测:`php backend/shared/tests/run.php`(无需 vendor/Swoole)

## 5. 管理后台 admin-web

```bash
cd admin-web
npm install
npm run dev        # http://localhost:5173
```

- 开发代理:`/api` → `http://127.0.0.1:8080`(vite.config.ts,指向 OpenResty 网关;未起网关时可临时改回单服务端口如 9501)
- 默认登录账号见 `database/seed/01-admin-role.sql`
- 构建验证:`npm run build`(零 TS 报错为验收标准)

## 6. 移动端 client-app

```bash
cd client-app
cp .env.example .env    # EXPO_PUBLIC_API_BASE_URL 指向网关
npm install
npm start               # Expo DevTools;按 a/i/w 分别启动 Android/iOS/Web
npm run typecheck       # tsc --noEmit 类型检查
```

- `EXPO_PUBLIC_API_BASE_URL` 默认 `http://localhost:8080`(网关聚合各微服务);
  网关未启动时,可临时指向单一服务端口逐服务联调(如 `http://localhost:9503` 调商品接口)
- 真机调试时需改为局域网 IP(手机与电脑同网段),`localhost` 在真机上不可达
- 接口约定见 `docs/guides/api/移动端接口规范.md`

## 7. 推荐启动顺序(手动方式)

1. MySQL / Redis
2. 后端各服务(9501-9508)
3. admin-web(5173)或 client-app(Expo)

## 8. 常见问题

| 问题 | 处理 |
| --- | --- |
| Windows 下 `composer install` 报 ext-swoole 缺失 | 使用 Docker/WSL2 运行后端;或 `composer install --ignore-platform-req=ext-swoole` 仅安装依赖做静态检查 |
| 401/40102 频繁 | 确认各服务 `MTRIP_JWT_SECRET` 一致且未过期(`MTRIP_JWT_TTL` 默认 7200s) |
| 移动端请求无数据 | 检查 `X-Site-Id` 站点是否启用、`.env` 网关地址、真机是否用了 `localhost` |
| 端口占用 | 修改对应服务 `.env` 的 `HTTP_PORT`,并同步调整前端代理/网关上游 |
| Windows 无 Docker/WSL2 虚拟机平台不可用(HCS_E_SERVICE_NOT_AVAILABLE)或 Docker Desktop 提示未检测到虚拟环境 | 按上文 2.0 节四步处理:确认 BIOS 虚拟化 → 启用「虚拟机平台」+ WSL 功能(无需 Hyper-V)→ 重启 → Docker Desktop 用 WSL2 后端 |
