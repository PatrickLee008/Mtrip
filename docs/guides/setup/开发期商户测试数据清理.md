# 开发期商户测试数据清理

入口：`scripts/reset-merchant-test-data.sh`。采用 Bash 编排 Docker、备份、SQL 事务与 Redis 清理，支持 macOS Bash 3.2、Linux 和 Windows Git Bash。需要 Docker 开发栈已启动，并已应用当前仓库数据库迁移。

## 使用

在仓库根目录先查看删除数量：

```bash
bash scripts/reset-merchant-test-data.sh
```

确认范围后执行：

```bash
bash scripts/reset-merchant-test-data.sh --execute --confirm DELETE_ALL_MERCHANT_TEST_DATA
```

默认仅预览。正式执行会物理删除所有站点的目标数据，包含软删除、封存、停用记录。它不按当前登录账号或站点过滤。

## 清理与保留

| 范围 | 行为 |
| --- | --- |
| 入驻线索 | 删除申请、首批业务、备注、协议签署、审核时间线、KYC 文件记录与历史版本、账号凭证投递 |
| 商户 | 删除正式商户、商户及门店账号、自定义角色和授权、认证挑战、代登录、物业、银行账户、黑名单、合规记录、通知和活动记录 |
| 商品 | 删除商户商品、酒店历史映射、房型和媒体记录、审核版本、库存/变动、退款规则、对应供应商商品关联 |
| 订单 | 删除相关预订、退款、核销、同步任务、聊天、消费者通知、评价/收藏、支付流水、账务、商户结算/提现、相关钱包/积分记录与推荐奖励关联 |
| Trip | 删除包含目标预订的行程；若同一行程还包含非目标订单，整次清理拒绝执行，需要先人工核对 |
| 营销与排名 | 删除商户优惠券、受影响的领券/促销码、曝光、活动商品/商户参与关系；移除平台活动的已删券引用，扣减保留平台券的相关领取/使用数量；清除商户榜单与发布快照，保留热门目的地 |
| 系统消息 | 删除 `scene` 以 `merchant_` 开头的邮件/短信发送日志，保留渠道和模板 |
| Redis | 删除注册 OTP/冷却键，以及已删账号的 App 配对码；保留集团配对码、消费者和平台缓存 |
| 基础数据 | 保留平台管理员、站点、消费者及余额/积分、供应商、集团及集团账号、内置角色、菜单、KYC 模板、入驻协议模板、分类、税务/营销规则、消息模板、渠道、迁移账本 |
| 文件与编号 | 保留共享文件库、磁盘/对象存储文件、自增 ID、商户编号序列、邮箱锁表；重新测试不会从 1 开始编号，空邮箱锁行不会占用邮箱 |

本脚本只重置测试记录，不执行真实支付退款、回补消费者余额/积分或冲销供应商/推广伙伴已结算金额。订单流水删除后消费者余额/积分仍保持原值。需要重新设置测试钱包时应另行显式操作。

共享文件库缺少可靠的商户所有权字段，文件还可能被多个业务引用；脚本删除 KYC/媒体业务记录，不删除共享文件及外部对象。

## 执行保障

1. 从实际运行容器读取数据库和 `APP_ENV`；只允许 `dev/local/test/testing`，连接任一目标库的容器必须使用同一数据库对。
2. 核对明确的表清单；新增未映射的 `merchant_*` 表、缺失表/字段、非 InnoDB 表或混合 Trip 会阻断。项目没有靠外键自动级联，未来新增关联表时必须同时维护此脚本与隔离回归。
3. 暂停连接目标库的原本运行的服务，阻止接口、定时任务和凭证投递并发写入。执行期间不要从宿主机或其他环境直接写目标库。
4. 完整备份业务库和系统库到 `deploy/backups/merchant-reset-时间-进程号.sql.gz`，文件权限受 `umask 077` 保护。备份失败立即停止。
5. 子表到主表的删除及营销引用修正放在一个 MySQL 事务里，不使用 `TRUNCATE`、不重置自增序列、不关闭外键检查。SQL 错误断开连接后回滚。
6. 数据库提交后选择性清理 Redis；此步骤与 MySQL 不构成跨系统事务。若 Redis 失败，脚本明确报错并给出备份位置，数据库删除已提交。
7. 正常结束、失败或收到 INT/TERM 时恢复原来运行的服务；同一 Compose 项目的运行网关会 reload，刷新上游 IP。外部自定义网关需自行刷新。可用 `bash deploy/mtrip.sh health` 检查恢复情况。

## 自定义环境与恢复

可覆盖 `MYSQL_CONTAINER`、`MYSQL_ROOT_PASSWORD`、`REDIS_CONTAINER`、`GATEWAY_CONTAINER`、`DB_BUSINESS_DATABASE`、`DB_SYSTEM_DATABASE`、`BACKUP_DIR`、`DOCKER`。默认密码从 MySQL 容器读取，Redis DB/密码从目标服务容器读取，不要求手工将密码写入命令。

备份包含两个库及存储过程、事件、触发器。恢复会覆盖这些库的数据；恢复前应停止写入，并确认要恢复的备份及恢复时点。

```bash
gunzip -c deploy/backups/merchant-reset-实际文件名.sql.gz | \
  docker exec -i mtrip-mysql-1 sh -c \
  'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysql -uroot --default-character-set=utf8mb4'
```

回归入口：

```bash
bash scripts/tests/test-reset-merchant-test-data.sh
```

回归会新建 `mtrip_merchant_reset_test`、`mtrip_merchant_reset_system_test`，只读克隆现有开发数据，并创建独立 Redis 和模拟写入服务容器。若测试库已存在则拒绝覆盖。完成后删除自己创建的库、容器和备份。覆盖预览、确认串、生产环境拒绝、未知表、混合 Trip、备份失败、后段 SQL 失败回滚、基础数据保留、Trip/订单与房型/票种 ID 碰撞、选择性 Redis 清理、备份及重复执行。
