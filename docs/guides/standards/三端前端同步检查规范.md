# 三端前端同步检查规范(admin-web / merchant-web / supplier-web)

三个管理类前端为**克隆架构**(同一套 Vue3 + AntD 框架代码按端复制),框架层文件(路由守卫、权限指令、组合式函数、请求封装)逻辑必须保持一致;任一端修复框架层缺陷后,**必须同步另外两端或在本文记录不适用原因**。是否收敛为共享包由所有者另行决策,本规范只保证克隆期不漂移。

## 同步检查文件清单

修改任一端下列文件时,必须用本文末尾的比对命令核对另外两端:

| 文件 | 职责 | 允许的端别差异(白名单) |
| --- | --- | --- |
| `src/router/guard.ts` | 登录态校验/动态路由恢复/页签与标题 | 无(必须逐字一致) |
| `src/router/dynamic.ts` | 菜单→动态路由构建/WIP 回退/KeepAlive | 仅注释:示例路径、菜单表名(sys_menu / merchant_menu / supplier_menu) |
| `src/router/index.ts` | 静态路由与 404 | 无 |
| `src/directives/perm.ts` | v-perm 按钮权限指令 | 仅注释:权限键前缀示例(sys: / mch: / sup:) |
| `src/composables/useTable.ts` | 列表页分页/加载组合式函数 | 无 |
| `src/utils/http.ts` | axios 封装/401 处理/签名加密 | 无 |
| `src/utils/auth.ts` | Token 存取 | 仅 `TOKEN_KEY` 常量(mtrip_admin_token / mtrip_merchant_token / mtrip_supplier_token) |
| `src/utils/crypto.ts` | 客户端签名/传输加密 | 无 |

白名单以外的任何差异都视为**未同步的修复**,必须补齐或在下方「比对记录」写明不适用原因。

## 比对记录

### 2026-07-30(基准:admin-web,覆盖 guard/dynamic/index/perm/useTable/http/auth)

- `router/guard.ts`、`router/index.ts`、`composables/useTable.ts`、`utils/http.ts`:三端**内容逐字一致**(guard.ts 仅行尾 LF/CRLF 差异,无语义影响);「登录态清理防死循环」修复三端均已同步。
- `router/dynamic.ts`:仅 3 处注释差异(示例路径 `system/admin/index` vs `account/index`;is_cache 注释中的菜单表名按端标注),逻辑零漂移 → **不适用,无需同步**。
- `directives/perm.ts`:仅注释差异(权限键前缀示例按端标注;admin 版注释保留「杜绝调试越权」原始表述,merchant/supplier 版表述为「与后端 #[Permission] 同一把钥匙」,语义等价),逻辑零漂移 → **不适用,无需同步**。
- `utils/auth.ts`:仅 `TOKEN_KEY` 按端不同,属白名单预期差异(三端可同域部署,Token 隔离是刻意设计)→ **不适用,无需同步**。
- 结论:**本轮未发现需要补齐的未同步修复**。

## 比对命令(修复框架层文件后必跑)

在仓库根目录执行(git 精确到字节,`--stat` 无输出即完全一致):

```powershell
# 以修改的文件为准,与另外两端两两比对,例:
git diff --no-index admin-web/src/router/guard.ts merchant-web/src/router/guard.ts
git diff --no-index merchant-web/src/router/guard.ts supplier-web/src/router/guard.ts
```

判定规则:

1. 无差异 → 通过;
2. 差异全部落在上表白名单内 → 通过,无需记录;
3. 白名单外差异 → 属未同步修复,当场同步三端,并在「已知坑同步状态」表追加一行;确属端别特有逻辑的,在「比对记录」写明不适用原因。
