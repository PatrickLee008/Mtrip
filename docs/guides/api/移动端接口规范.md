# 移动端接口规范(client-app ↔ /api/v1/app/*)

> 适用范围:`client-app/`(Expo 51 + RN)对接后端微服务(模块09)。管理后台接口规范见 `/api/v1/admin/*` 相关文档。
> 更新时间:2026-07-28

## 1. 微服务与端口

| 服务 | 端口 | C端职责 | 与管理端的关系 |
| --- | --- | --- | --- |
| system-service | 9501 | 公开站点列表/站点配置 | 公用服务,C端仅暴露 `AppSiteController` 两个公开接口 |
| user-service | 9502 | C端注册/登录/个人中心 | 移动端为主,管理端用户管理接口由模块06 补充 |
| goods-service | 9503 | 首页/分类/列表/详情/价格日历 | 公用服务,双前缀路由(admin 前缀归模块06) |
| order-service | 9504 | 下单/支付mock/订单/退款申请/核销码 | 公用服务,双前缀路由(admin 前缀归模块06) |

公用微服务采用**双前缀路由**方案:同一服务同时挂 `/api/v1/admin/*`(AdminAuthMiddleware)与
`/api/v1/app/*`(UserAuthMiddleware,JWT `aud=app`),业务代码按前缀隔离控制器。

## 2. 请求规范

### 2.1 请求头(request.ts 自动携带)

| Header | 说明 |
| --- | --- |
| `Authorization` | `Bearer {token}`,登录后携带(JWT aud=app) |
| `X-Site-Id` | 当前站点 ID,**所有接口必带**(多站点数据隔离) |
| `X-Client-Type` | `app-ios` / `app-android` / `app-h5` |
| `X-Timestamp` | 毫秒时间戳 |
| `X-Lang` | `zh-CN` / `en-US` |

### 2.2 统一响应

```json
{ "code": 0, "message": "success", "data": {}, "timestamp": 1753689600 }
```

分页 data 结构:`{ "list": [], "total": 0, "page": 1, "pageSize": 10 }`

### 2.3 错误码(前端需感知)

| code | 含义 | 前端处理 |
| --- | --- | --- |
| 0 | 成功 | — |
| 40001 | 参数错误 | Toast message |
| 40101 / 40102 | 未认证 / Token 过期 | 清本地登录态,引导登录 |
| 40301 | 无权限 | Toast |
| 40401 | 资源不存在 | Toast / 空态 |
| 40901 | 数据冲突(如库存不足) | Toast message |

### 2.4 数据形态约定

- **user 模块**返回 camelCase 且已脱敏(如 `memberLevelName`、`mobile` 为 `138****8000`)
- **goods / order / site 模块**返回数据库 snake_case 原始行(如 `goods_name`、`order_status`)
- 前端类型定义见 `client-app/src/types/models.ts`,与该约定严格一致

## 3. 接口清单

### 3.1 system-service — 站点(公开)

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/app/site/list` | 启用站点列表(公开字段) |
| GET | `/api/v1/app/site/config` | 站点信息 + `config_group='app'` 配置;`siteId` 参数或 `X-Site-Id` 头 |

### 3.2 user-service — 认证与个人中心

公开(须带 X-Site-Id):

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/app/auth/register` | 注册,body: `mobile/password/nickname?`,返回 `{token, expiresIn, user}` |
| POST | `/api/v1/app/auth/login` | 登录,同上返回 |

需登录:

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/app/auth/logout` | 登出 |
| POST | `/api/v1/app/auth/refresh` | 刷新 token |
| GET | `/api/v1/app/user/me` | 个人资料(camelCase 脱敏) |
| POST | `/api/v1/app/user/update` | 修改昵称/头像等 |
| POST | `/api/v1/app/user/change-password` | 修改密码 |
| GET | `/api/v1/app/user/balance-logs` | 余额流水(分页) |
| GET | `/api/v1/app/user/points-logs` | 积分流水(分页) |
| POST | `/api/v1/app/user/feedback/add` | 提交反馈 |
| GET | `/api/v1/app/user/feedback/list` | 反馈列表(分页) |

### 3.3 goods-service — 商品(全部公开)

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/app/goods/home` | 首页推荐/热门各8条 `{recommend, hot}` |
| GET | `/api/v1/app/goods/category` | 两级分类树,`goodsType?` |
| GET | `/api/v1/app/goods/list` | 分页,`keyword/goodsType/categoryId/starLevel/sortBy(default,sales,new)` |
| GET | `/api/v1/app/goods/detail` | `id`;商品+SKU+退改规则+`minPrice`(剔除审核字段) |
| GET | `/api/v1/app/goods/calendar` | `skuType/skuId/startDate?/days?(≤90)`;无日历记录按 SKU 基础价/库存回退 |

### 3.4 order-service — 订单(全部需登录)

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/app/order/create` | 下单锁库存,body: `goodsId/skuId/quantity/useDate/endDate?(酒店必填)/contactName/contactPhone/remark?`,返回 `{orderId, orderNo}` |
| POST | `/api/v1/app/order/pay` | **mock 支付**,`orderId/payMethod(1 Stripe 2 PayPal)`,成功生成核销码并扣减库存 |
| GET | `/api/v1/app/order/list` | 分页,`status?`(0-7) |
| GET | `/api/v1/app/order/detail` | `orderId`;联系人电话脱敏,非已支付/已核销态不返回核销码 |
| POST | `/api/v1/app/order/cancel` | 仅待支付可取消,释放库存 |
| POST | `/api/v1/app/order/refund/apply` | 仅已支付可申请,`orderId/reason/images?`;仅提交申请单,审核归模块06 |
| GET | `/api/v1/app/order/verify-code` | 仅已支付/已核销态可查,16位码 |

订单状态:`0待支付 1已支付 2已核销 3已完成 4已取消 5退款中 6已退款 7已过期`

### 3.5 待模块06 落地的接口(前端暂未封装)

- `marketing-service`:优惠券/活动(`client-app/src/api/marketing.ts` 待补)
- `payment-service`:正式 Stripe/PayPal 收单(当前 `pay.ts` 指向 order-service mock,拆分后仅需调整路径)

## 4. 前端请求层要点(client-app/src/api/request.ts)

- Axios 单例,超时 15s;响应拦截统一解析 `{code,message,data}`,非 0 抛 `ApiError(code, message)` 并 Toast
- 40101/40102 触发 `onUnauthorized` 清本地登录态
- 钩子注入模式:`setRequestHooks()` 由 `bootstrapStores()` 注册 token/siteId/lang 提供者,避免循环依赖
- 环境变量:`EXPO_PUBLIC_API_BASE_URL` 等,见 `client-app/.env.example` 与 `src/config/env.ts`
