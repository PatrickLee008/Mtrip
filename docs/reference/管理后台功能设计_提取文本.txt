第二部分 系统底层基础模块（11个模块）
模块 1：管理员账号管理模块
1. 功能概述
管理后台所有登录操作员账号，区分超级管理员、站点运营账号；支持账号增删改查、状态启停、角色绑定、重置密码，所有操作留日志。
2. 核心字段
账号 ID、登录账号、登录密码（加密存储）、管理员姓名、绑定角色 ID、所属站点 ID（超级管理员站点 ID 为 0，代表全平台）、手机号、邮箱、账号状态（启用 / 禁用）、创建时间、最后登录时间、备注
3. 完整功能清单
账号列表分页查询：支持按账号名称、站点、状态筛选
新增管理员账号
超级管理员可创建全平台账号、各站点管理员
站点管理员仅能创建本站点子运营账号
创建时必须绑定至少 1 个角色，设置初始密码
编辑管理员信息：可修改姓名、手机号、邮箱、绑定角色、备注；不允许修改所属站点 ID
重置密码：管理员忘记密码时，超级 / 站点管理员可一键重置为初始密码
启用 / 禁用账号：禁用后账号无法登录后台
查看账号登录记录：展示该账号所有登录时间、登录 IP、设备信息
批量删除 / 批量禁用账号
4. 权限控制
菜单权限：系统管理 - 管理员管理
按钮权限：新增、编辑、重置密码、启用 / 禁用、批量操作、查看登录记录、删除
模块 2：角色权限管理模块
1. 功能概述
基于 RBAC 权限模型，角色作为权限载体；给角色绑定菜单、按钮、接口权限，管理员绑定角色后自动继承全部权限；支持区分平台全局角色、站点独立角色。
2. 核心字段
角色 ID、角色名称、角色类型（全局角色 / 站点角色）、所属站点 ID（全局角色为 0）、角色描述、创建时间、状态（启用 / 禁用）
3. 完整功能清单
角色列表分页查询：按角色名称、类型、站点筛选
新增角色
全局角色：超级管理员创建，全平台所有站点可复用
站点角色：站点管理员创建，仅当前站点可用
编辑角色基础信息
权限分配（核心功能）
树形结构展示全平台菜单，分层勾选：
① 勾选页面菜单（拥有页面访问权限）
② 展开菜单，勾选页面内操作按钮（新增 / 编辑 / 删除 / 导出 / 审核等）
③ 自动关联对应后端 API 接口权限，后端双重校验
查看绑定管理员：展示当前角色下所有管理员账号
启用 / 禁用角色：禁用后绑定该角色的管理员自动失去全部权限
删除角色：仅无管理员绑定的角色可删除
4. 权限控制
菜单权限：系统管理 - 角色管理
按钮权限：新增、编辑、分配权限、查看绑定账号、启用禁用、删除
模块 3：菜单 &amp; 按钮权限管理模块
1. 功能概述
维护后台全部页面菜单、页面内操作按钮、对应 API 权限标识；构建树形菜单结构，精确控制每一个页面、每一个操作按钮的访问权限，是整个权限体系的底层数据源。
2. 核心字段
菜单 ID、父级菜单 ID（树形层级）、菜单名称、菜单标识（唯一权限 key，后端接口校验使用）、路由地址（前端页面路由）、图标、菜单类型（一级菜单 / 页面菜单 / 页面按钮）、排序号、状态（显示 / 隐藏）、备注
3. 完整功能清单
菜单树形列表展示，支持折叠展开
新增菜单 / 按钮
一级菜单：分类目录，无页面路由
页面菜单：对应后台独立页面，填写前端路由
页面按钮：依附于页面菜单，填写按钮唯一权限标识（如 sys:admin:add）
编辑菜单信息：修改名称、路由、图标、排序、状态
上下排序：调整菜单展示顺序
显示 / 隐藏菜单：隐藏后侧边栏不展示，但权限仍可分配给角色
删除菜单：存在子菜单 / 按钮时禁止删除
批量同步权限标识：统一维护前端按钮与后端接口的权限 key，避免权限校验不匹配
4. 权限控制
菜单权限：系统管理 - 菜单管理
按钮权限：新增、编辑、排序、显示隐藏、删除
模块 4：系统操作日志模块
1. 功能概述
全后台所有管理员操作永久记录，不可删除、不可修改；用于操作审计、安全追溯，满足海外 GDPR 合规审计要求；自动记录操作人员、站点、操作内容、IP、时间。
2. 核心字段
日志 ID、管理员账号、管理员姓名、所属站点 ID、操作模块（管理员 / 角色 / 存储 / 支付等）、操作类型（新增 / 编辑 / 删除 / 导出 / 登录 / 重置密码）、操作详细内容（记录修改前后数据）、请求接口地址、客户端 IP、操作系统 / 浏览器、操作时间
3. 完整功能清单
日志分页查询：支持按操作人、操作模块、操作时间范围、站点筛选
日志详情查看：完整展示操作内容、修改前后数据、IP、设备信息
日志导出 Excel：导出筛选后的日志记录，用于财务、合规审计
日志自动清理配置（配套系统配置模块）：可设置 365/730 天自动归档老旧日志
4. 权限控制
菜单权限：系统管理 - 操作日志
按钮权限：查看详情、导出日志
5. 约束规则
所有日志数据禁止手动删除、编辑，仅能通过系统定时任务自动归档
6. 补充新增操作类型（适配客户端、接口权限模块）
新增客户端、重置客户端秘钥、修改客户端限流/IP白名单、新增接口权限模板、修改模板接口权限、绑定客户端权限模板、启停客户端/权限模板
模块 5：全局系统配置模块
1. 功能概述
全平台通用基础参数配置，全局生效，所有站点共用；控制系统基础运行参数、安全策略、文件上传限制、登录规则、客户端、接口日志底层规则。
2. 核心配置项分类
（1）平台基础配置
平台名称、平台 Logo、后台登录页标语、官网地址、客服邮箱、客服联系电话、后台登录有效期（Token 过期时长）
（2）安全策略配置
登录错误锁定次数、账号锁定时长、密码强度规则（长度、大小写、数字符号）、是否开启登录 IP 校验、是否强制开启 HTTPS、操作日志自动归档天数
（3）上传通用限制
全局允许上传文件格式、单文件最大大小、图片压缩尺寸、是否开启上传文件水印
（4）客户端&amp;接口日志全局配置
接口日志自动归档存储天数
客户端默认 QPS 限流阈值
客户端秘钥自动过期周期
接口调用日志是否开启敏感参数自动脱敏
3. 完整功能清单
配置表单可视化编辑，分类标签页切换
配置一键重置为系统默认值
配置修改日志记录，所有参数变更留存操作记录
预览 Logo、水印图片
4. 权限控制
菜单权限：系统配置 - 全局参数配置
按钮权限：编辑配置、重置默认、预览图片
模块 6：多站点配置模块（平台核心模块）
1. 功能概述
适配项目多城市、多区域站点架构；管理全球所有区域 / 城市站点基础信息、站点独立差异化参数；站点数据隔离的核心底层配置。
2. 核心字段
站点 ID、站点名称、站点类型（国家 / 区域 / 城市）、上级站点 ID（树形层级，如欧洲→法国→巴黎）、站点域名（独立 H5 / 后台域名）、所属地区（时区、国家编码）、默认货币单位、默认语言、站点状态（启用 / 停用）、站点联系人、联系邮箱、站点备注、创建时间
3. 站点独立差异化配置（每个站点独立参数）
本地化配置：默认语言、默认时区、本地货币、VAT 增值税税率
页面配置：站点独立首页 banner、站点 Logo、站点客服联系方式
运营配置：站点是否开启商户入驻、站点抽佣基础比例、是否开启该站点门票 / 酒店业务
推送配置：站点独立推送模板、短信签名
4. 完整功能清单
站点树形分页列表，按区域、站点名称、状态筛选
新增站点：选择上级区域，填写域名、时区、货币等基础信息
编辑站点基础信息 + 站点差异化运营参数
启用 / 停用站点：停用后 C 端 APP/H5 无法进入该站点，站点管理员无法登录后台
查看站点绑定管理员、绑定商户列表
站点数据统计预览：该站点用户、订单、营收简易统计
删除站点：站点下无商户、无订单、无管理员才可删除
5. 权限控制
菜单权限：站点管理 - 站点配置
按钮权限：新增站点、编辑站点、启用 / 停用、查看绑定账号商户、删除
模块 7：文件存储管理模块
1. 功能概述
统一管理平台全部静态资源存储配置（酒店图片、门票海报、后台上传文件、用户头像等）；支持多存储驱动切换（Cloudflare R2、AWS S3、本地存储），支持各站点独立存储桶配置。
2. 核心配置字段

（供应商结算）结算单ID、供应商ID、结算周期、供货总金额、分成金额、已回款金额、待回款金额、结算状态
（资金流水）流水ID、流水号、流水类型（收入/支出/转账/冻结/解冻）、金额、关联订单ID、关联商户ID、支付渠道、流水状态、创建时间、备注
3. 完整功能清单
3.1 平台资金总览
资金大盘：总营收、今日营收、本月营收、待结算、已结算、平台佣金统计
营收趋势图：日/周/月营收趋势、订单量趋势
资金构成：各支付渠道占比、各站点营收占比、各商户营收排行
3.2 商户结算管理
商户结算单：按结算周期自动生成商户结算单
分账明细：每笔订单的分账记录（订单金额、平台佣金、商户实收）
商户提现申请：商户发起提现申请，填写金额和账户
提现审核：财务审核提现申请，通过/驳回
提现执行：审核通过后，打款到商户账户，记录凭证
提现流水：所有提现操作的完整记录
月度对账单：按月生成商户对账单，支持导出Excel
3.3 供应商结算管理
供应商结算单：按月/按周期生成供货结算单
供货分成明细：每笔供货订单的分成计算
回款审核：供应商回款申请审核
回款执行：付款给供应商，记录付款凭证
回款流水：所有回款操作记录
3.4 全局资金流水
资金流水总览：所有资金进出的完整流水账
流水筛选：按流水类型、时间、金额、关联对象筛选
流水详情：每笔流水的详细信息、关联业务单据
流水导出：批量导出资金流水Excel
3.5 税费配置管理
VAT税率配置：各站点增值税税率配置
税费计算规则：含税价/不含税价计算方式
税费统计：各站点税费收入统计报表
税务申报数据导出：支持导出税务申报所需数据
4. 权限控制
菜单权限：财务管理 - 资金总览 / 商户结算 / 供应商结算 / 资金流水 / 税费配置
按钮权限：查看结算单、审核提现、执行打款、导出对账单、导出流水、配置税率、手动调账（需超级管理员）
5. 业务规则与约束
订单支付成功后，自动进行分账计算：平台佣金 = 订单金额 × 抽佣比例，商户实收 = 订单金额 - 平台佣金
商户资金进入待结算状态，过了结算周期（如T+7）后转为可提现余额
提现审核需二级审批：一级财务审核，二级主管复核
所有资金流水永久留存，不可删除、不可修改，确保财务可审计
退款时，平台佣金和商户实收按比例退回
税费按站点独立配置，支持不同国家/地区不同税率
手动调账功能仅限超级管理员，且需记录详细原因，操作日志永久留存
模块 7：营销活动管理模块（站点独立营销）
1. 功能概述
平台营销工具集合，为运营人员提供多样化的营销活动配置能力；包括优惠券、限时活动、首页推荐、积分活动等营销工具；各站点独立配置营销活动，实现差异化运营策略。
2. 核心字段
（优惠券）券ID、券名称、券类型（满减券/折扣券/代金券）、面值/折扣比例、使用门槛（最低消费金额）、适用范围（全场/指定商品/指定商户/指定分类）、所属站点ID、发放总量、已领取数量、每人限领数量、有效期类型（固定时间段/领取后N天有效）、有效期开始/结束、领取方式（手动领取/自动发放/活动赠送）、券状态（未开始/进行中/已结束/已停用）、创建时间
3. 完整功能清单
3.1 优惠券管理
优惠券列表：按站点、类型、状态筛选查询
新增优惠券：配置券类型、面值、门槛、适用范围、有效期
优惠券编辑：修改券信息（进行中的券部分字段不可改）
优惠券启停：启用/停用优惠券
优惠券发放记录：查看每张券的领取和使用情况
手动发券：给指定用户/用户群体发放优惠券
优惠券统计：领取量、使用量、核销量、带动GMV
3.2 限时活动管理
活动列表：限时特价、限时秒杀活动列表
创建活动：设置活动名称、时间、参与商品、折扣力度
活动商品管理：添加/移除活动商品，设置活动价格
活动库存：活动商品专属库存，售完即止
活动启停：手动开启/关闭活动
活动数据统计：活动销量、销售额、转化率
3.3 首页推荐配置
Banner管理：首页轮播图配置，图片、跳转链接、排序
热门推荐：热门酒店、热门门票推荐位配置
金刚区/功能入口：首页功能入口图标配置
各站点独立配置：不同站点首页内容差异化
定时上下架：Banner和推荐位支持定时生效
3.4 积分活动配置
积分获取规则：下单送积分、评价送积分、签到送积分
积分消耗规则：积分抵扣现金、积分兑换优惠券
积分兑换商品：配置可用积分兑换的商品/优惠券
积分有效期：积分过期规则配置
积分流水：所有积分变动记录
4. 权限控制
菜单权限：营销管理 - 优惠券 / 限时活动 / 首页推荐 / 积分活动
按钮权限：新增活动、编辑、启用/停用、删除、手动发券、导出数据、查看统计
5. 业务规则与约束
优惠券使用时，优先计算优惠金额，再计算平台佣金（佣金按实付金额计算）
同一订单最多使用一张优惠券，不可叠加
限时活动商品库存独立管理，活动结束后未售完库存回滚
首页推荐配置支持预览功能，确认无误后再发布
积分抵扣有上限，不能100%抵扣，需设置最低支付金额
所有营销活动各站点独立配置，互不影响
活动删除为软删除，已发放的优惠券仍可使用至过期

大数据量报表支持异步导出，生成后通知下载
模块 9：核销管理模块（线下景区 / 酒店核销终端）
1. 功能概述
管理线下核销设备和核销规则，实现门票/酒店订单的线下核验核销；支持多种核销方式（扫码、身份证、核销码），管控核销终端设备，记录全量核销日志，确保线下履约可追溯、可审计。
2. 核心字段
（核销设备）设备ID、设备编号、设备名称、设备类型（扫码枪/手持终端/闸机/前台电脑）、所属站点ID、绑定商户ID、绑定景区/酒店ID、设备密钥、设备状态（未激活/正常/故障/停用）、最后心跳时间、创建时间、备注
（核销规则）规则ID、规则名称、适用商品类型、核销有效期、单人单日核销次数限制、是否支持部分核销、过期处理方式（自动退款/作废）、核销时间范围
3. 完整功能清单
3.1 核销设备管理
设备列表：所有核销终端设备列表，按站点、商户、状态筛选
新增设备：添加核销终端，分配设备编号和密钥
设备绑定：将设备绑定到指定商户/景区/酒店
设备启停：启用/禁用设备，禁用后设备无法核销
设备状态监控：在线状态、最后心跳、核销次数统计
设备密钥重置：设备密钥泄露时重置
3.2 核销规则配置
核销规则列表：各站点/商品类型的核销规则
新增规则：配置核销有效期、次数限制、时间范围
规则绑定：将规则绑定到指定商品/票种
过期规则配置：过期未核销订单的处理方式
3.3 全量核销日志
核销日志列表：所有核销操作记录，支持多条件筛选
核销详情：核销时间、设备、操作员、订单信息、核销状态
核销异常记录：核销失败、重复核销、越权核销等异常记录
核销统计：按设备、按日期、按商品统计核销量
核销日志导出：导出核销记录Excel
3.4 核销操作功能
手动核销：后台手动核销订单（特殊场景，需记录原因）
撤销核销：核销错误时撤销，需审批
补核销：订单已使用但未核销时的补录
4. 权限控制
菜单权限：核销管理 - 设备管理 / 核销规则 / 核销日志
按钮权限：新增设备、编辑、绑定、启停、重置密钥、配置规则、手动核销、撤销核销、导出日志
5. 业务规则与约束
核销设备必须绑定站点和商户，设备仅能核销绑定范围内的订单
每次核销操作必须记录：核销时间、设备ID、操作员、订单号、核销状态
同一订单不可重复核销，重复核销返回错误并记录异常
核销操作不可逆，撤销核销需审批且记录详细原因
核销日志永久留存，不可删除，用于审计和纠纷处理
设备与服务器心跳检测，超时未心跳标记为离线
第五部分 数据库设计规范与核心表结构
5.1 数据库设计规范
• 数据库类型：MySQL 8.0+，字符集 utf8mb4，排序规则 utf8mb4_unicode_ci
• 表命名规范：模块前缀_表名，如 sys_admin、merchant_info、order_main
• 字段命名规范：小写下划线，如 created_at、site_id
• 主键统一使用：id BIGINT UNSIGNED AUTO_INCREMENT
• 所有表必须包含：created_at、updated_at、deleted_at（软删除）
• 所有业务表必须包含：site_id（站点隔离）
• 金额字段统一使用：decimal(12,2)
• 状态字段使用：tinyint，配合枚举注释
• 索引规范：主键索引、唯一索引、普通索引分开命名
• 分库分表：订单表、流水表、接口日志表按时间分表，单表数据量控制在500万以内

第六部分 API接口设计规范
6.1 接口设计规范
• 协议：HTTPS RESTful API
• 数据格式：JSON，统一 UTF-8 编码
• 请求方式：GET（查询）、POST（新增/操作）、PUT（修改）、DELETE（删除）
• 版本控制：URL路径版本号，如 /api/v1/、/api/v2/
• 鉴权方式：后台管理端 JWT Token（Header: Authorization: Bearer xxx）；移动端 ClientId + Sign 签名
• 分页参数：page（页码，从1开始）、pageSize（每页条数，默认20，最大100）
• 时间格式：ISO 8601，如 2026-07-28T12:00:00+08:00
• 接口域名：后台管理 admin-api.xxx.com；移动端 api.xxx.com
6.2 统一响应格式
成功响应：
{  "code": 0,  "message": "success",  "data": { ... },  "timestamp": 1722139200}
分页响应：
{  "code": 0,  "message": "success",  "data": {    "list": [...],    "total": 100,    "page": 1,    "pageSize": 20  }}

第七部分 业务状态流转与关键流程
7.1 订单状态机设计
7.1.1 酒店订单状态流转
状态枚举：待支付(0) → 已支付/待入住(1) → 已入住(2) → 已完成(3)
分支状态：已取消(4)、退款中(5)、已退款(6)
状态流转规则：
• 待支付 → 已支付：用户支付成功
• 待支付 → 已取消：用户取消 / 超时未支付自动取消
• 已支付 → 已入住：用户到店办理入住 / 到店日期自动变更
• 已支付 → 退款中：用户申请退款（入住前）
• 退款中 → 已退款：退款审核通过，资金退回
• 退款中 → 已支付：退款审核驳回
• 已入住 → 已完成：离店日期后自动完成
• 已完成 → 退款中：特殊情况售后退款（需审批）
7.1.2 门票订单状态流转
状态枚举：待支付(0) → 已支付/待核销(1) → 已核销(2) → 已完成(3)
分支状态：已取消(4)、退款中(5)、已退款(6)、已过期(7)
状态流转规则：
• 待支付 → 已支付：支付成功
• 待支付 → 已取消：用户取消 / 超时自动取消
• 已支付 → 已核销：扫码核销成功
• 已支付 → 退款中：用户申请退票
• 已支付 → 已过期：超过使用日期未核销
• 退款中 → 已退款：退款审核通过
• 已核销 → 已完成：核销当日结束自动完成
• 已过期 → 退款中：过期后申请退款（视退改规则）
7.2 商户入驻流程
1. 商户提交入驻申请：填写企业信息、上传资质文件
2. 平台初审：审核资料完整性，1个工作日内
3. 资质核验：核验营业执照真实性、法人身份
4. 审核通过：开通商户后台账号，发送登录信息
5. 商户登录配置：商户登录后台，完善店铺信息、配置结算账户
6. 商品上架：商户添加商品，提交平台审核
7. 商品审核：平台审核商品信息，通过后上架C端
8. 正式运营：商户开始正常经营
7.3 下单支付流程
1. 用户选商品：浏览商品，选择规格（房型/票种）、日期、数量
2. 提交订单：确认订单信息，提交订单
3. 库存校验：校验商品库存是否充足，锁定库存
4. 订单创建：生成待支付订单，返回支付信息
5. 用户支付：选择支付方式，完成支付
6. 支付回调：支付渠道异步通知支付结果
7. 订单状态更新：支付成功 → 已支付状态，扣减库存
8. 分账计算：计算平台佣金、商户实收、供应商成本
9. 通知用户：发送支付成功短信/推送
7.4 退款流程
1. 用户申请退款：在订单详情页申请退款，选择退款原因
2. 退款金额计算：根据退改规则自动计算可退金额
3. 商户审核（可选）：商户先审核退款申请
4. 平台审核：平台财务/客服最终审核
5. 退款执行：审核通过后，调用支付渠道退款接口
6. 退款回调：支付渠道异步通知退款结果
7. 订单状态更新：退款成功 → 已退款状态，库存回滚
8. 资金回退：平台佣金、商户实收按比例退回
9. 通知用户：发送退款成功通知
7.5 商户结算流程
1. 订单完成：订单完成后，商户金额进入待结算状态
2. 结算周期：过了结算周期（如T+7），金额转为可提现余额
3. 商户申请提现：商户在后台发起提现申请
4. 财务审核：平台财务审核提现申请
5. 主管复核：大额提现需主管二次复核
6. 执行打款：审核通过后，财务打款到商户账户
7. 记录凭证：上传打款凭证，更新提现状态
8. 通知商户：发送提现到账通知
7.6 商品审核流程
1. 商户创建商品：商户在后台添加商品信息
2. 商户提交审核：商户确认信息无误后提交平台审核
3. 平台审核：平台运营审核商品信息合规性
4. 审核通过：商品自动上架C端展示
5. 审核驳回：填写驳回原因，退回商户修改
6. 商户修改：商户根据驳回意见修改商品信息
7. 重新提交：商户修改完成后重新提交审核

第九部分 全局统一约束规范
9.1 数据隔离规范
所有配置、日志、商户、商品、订单、客户端数据全部携带 site_id；site_id=0 为平台全局数据，仅超级管理员可查看编辑；站点管理员仅能操作所属 site_id 数据，跨站点数据自动过滤隐藏，实现站点数据完全隔离，满足海外 GDPR 数据本地化存储合规要求。
9.2 密钥数据安全规范
所有第三方服务密钥（存储 AK/SK、支付密钥、短信密钥、地图 Key）、客户端 ClientSecret 全部使用 AES 对称加密存储于数据库；前端页面统一脱敏展示（仅展示首尾字符，中间星号隐藏）；仅平台超级管理员拥有查看完整明文密钥权限，站点管理员、商户管理员无法查看任何密钥明文。
9.3 审计日志强制规范
后台管理员任何新增、编辑、删除、配置修改操作，自动写入【系统操作日志】，永久存储，后台无任何删除、编辑日志入口，仅定时任务可按配置自动归档。
移动端 App/H5 所有 API 接口请求全量写入【接口调用日志】，敏感参数自动脱敏，支持异常排查、流量统计、合规审计。
资金流水、核销记录、订单退款记录永久归档，不可手动删除，满足海外财务、监管审计要求。
9.4 权限双层校验规范
后台管理员访问页面、操作按钮：第一层校验 RBAC 角色菜单 / 按钮权限；第二层校验站点数据隔离权限，无权限页面、按钮自动隐藏，无数据权限自动过滤数据。
移动端客户端调用业务 API：第一层校验 ClientId + 签名秘钥合法性、IP 白名单、QPS 限流、客户端过期状态；第二层校验绑定的接口权限模板，禁止调用模板黑名单接口、仅允许白名单接口访问，任意一层校验失败直接拦截接口，返回标准化鉴权失败 JSON。
9.5 前端页面统一规范
全部页面基于 Ant Design Vue Pro 组件开发；所有列表页面统一支持分页、多条件组合筛选、Excel 导出功能；表单弹窗完善表单校验规则；无权限操作按钮由后端动态返回权限标识，前端自动隐藏，避免前端静态写死按钮导致越权操作漏洞。
9.6 后端接口统一规范
所有接口统一携带 JWT 管理员 Token（后台管理端）/ ClientId + 签名（移动端客户端）；后端双重权限校验，返回统一标准化 JSON 格式。
异常状态码规范：401 未登录 / 鉴权失败、403 无操作权限、429 请求限流、500 服务异常。
9.7 软删除规范
所有业务数据删除均为软删除，通过 deleted_at 字段标记删除状态，数据物理保留在数据库中；删除数据默认不在列表中展示，特殊场景可查询回收站数据；确保数据可追溯、可恢复。
9.8 时间与时区规范
数据库统一存储 UTC 时间，前端根据用户所在站点时区自动转换显示；所有时间字段使用 DATETIME 类型，精确到秒；跨时区操作时，以服务器时间为准。
9.9 金额计算规范
所有金额计算使用 decimal 类型，禁止使用 float/double 类型；金额计算保留2位小数，四舍五入；分账计算时，先算总金额，再按比例分配，确保分账总和等于总金额，避免精度丢失。
