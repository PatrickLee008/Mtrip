# 模块16:运维监控与发布管理(Mtrip Ops)

状态:进行中(Docker sudo 诊断增强) | 进度:54% | 依赖:deploy/mtrip.sh、scripts/auto-deploy.sh、deploy/logs | 更新时间:2026-09-02

## 目标

在 `mtrip-ops/` 独立目录建设一套轻量运维服务软件,不与 Mtrip 业务前后端耦合,用于统一查看平台运行状态、服务健康、业务日志、流量、在线用户、服务负载与发布管理。

## 技术方案

- 技术栈:Node.js 单体服务 + 服务端渲染 HTML + 少量 CSS,第一版零依赖,不做前后端分离。
- 运行方式:默认绑定 `127.0.0.1:56700`,通过 `ops.config.json` 配置项目路径、日志目录、网关地址、Docker 命令和动作开关。
- 数据来源:
  - `deploy/mtrip.sh status/health`
  - `scripts/auto-deploy.sh --dry-run`
  - `deploy/logs/*/request-*.log` 与 `hyperf-*.log`
  - 主池 8 服务直连 `/healthz`
  - APP 孪生池作为独立内网服务后续容器内探测
- 安全边界:默认只读、动作显式 `enableActions=true`、命令白名单、`execFile` 禁 shell 拼接、审计写 `mtrip-ops/data/audit.log`。

## 风险与待修正

- `scripts/auto-deploy.sh` 当前 DB 变更匹配需要覆盖 `database/*/*.sql`,否则子目录迁移可能漏报。
- `deploy/mtrip.sh` 内部 `detect_compose()` 仍直接调用 `docker compose`,与文档里的 `DOCKER='sudo docker'` 能力不完全一致。
- 如后续接 Docker socket,必须用 socket proxy 或受限 runner,避免 Web 进程等同宿主 root。
