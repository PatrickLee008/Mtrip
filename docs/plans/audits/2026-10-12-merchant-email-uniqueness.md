# 商户邮箱唯一性整改与存量处理

日期：2026-10-12。范围：后端、数据库、后台门禁文案、Merchant Web 登录提示；未修改 Merchant App 和用户 App 源码。

## 实现与规则

- 注册／登录邮箱全平台唯一，去首尾空格并转小写，沿用 HMAC 检索哈希。业务／物业联系人邮箱不承担登录身份，不受此约束；同一商户账号可以管理多个物业。
- 注册发码前检查占用，验证 OTP 创建草稿时在事务内再次检查。同站点、同手机号、同邮箱且尚无正式账号时可恢复原申请；不同手机号或站点不得借邮箱取得原申请 token。正式账号已存在时拒绝新建，引导登录／联系管理员。
- 后台代录和最终批准共用占用校验；审批冲突时整体回滚，不产生部分商户、账号或物业。readiness 增加 `registration_email_conflict`，后台已有原因映射显示中英文说明。
- `MerchantEmailIdentityService::transaction` 先锁定邮箱哈希对应的一行，再读取两张归属表并写入，覆盖注册／代录／最终批准。所有调用方在取得锁后才建立事务读取快照；占用查询走全局生成列索引，不对不存在的归属记录加范围锁，避免不同邮箱相互死锁。
- 申请和账号分别通过生成列建立全平台唯一索引，不包含 `site_id`。待激活、停用、驳回、注销和普通软删除不释放邮箱；只有经过授权／审计的显式释放标记才使唯一键为 NULL。历史密文、哈希保留。
- 遗留重复账号不被随机选中，登录不发码且记录脱敏活动。Web 登录使用条件式发送说明，邮箱／短信 OTP 后仍须 Authenticator。渠道与测试开关未改。
- 删除／释放账号不能重发未完成的激活凭证。当前子账号接口无邮箱写入字段，旧商户／门店开户也不复制注册邮箱，未新增换绑接口。今后增加邮箱写入时须使用同一事务锁与唯一校验，新邮箱通过真实 OTP 后才能启用登录。

## 迁移与部署

1. 在旧服务仍运行时只读审计：容器内 `php bin/audit-email-identities.php`，只输出脱敏邮箱、关联 ID 和异常类型；存在冲突或密文／哈希异常返回退出码 2，覆盖软删除但未显式释放的数据。
2. `V20261012130000__add-merchant-email-identity-lock.sql` 增加锁表、账号 `email_released_at`、申请 `registration_email_released_at`。
3. 人工确认并审计处理重复归属，不能按创建时间选择账号，不能清空哈希伪装解决；换绑须完成验证、使旧验证上下文失效。
4. 审计通过后执行 `V20261012130100__enforce-merchant-email-uniqueness.sql`。未处理的重复申请／账号、跨表归属冲突或缺失索引会在业务表 DDL 前停止，不自动删除或合并数据。
5. 标准发布执行 `bash scripts/db-migrate.sh` 后加载代码、刷新代理／重启商户双池、发布两个 Web，不能只发代码跳过迁移。空库不再另设快照,由 MySQL 镜像内 `99z-run-migrations.sh` 执行同一批版本迁移。

本机账本 37/37；Admin Web、Merchant Web 已构建并发布到本地网关，商户主池与 App 池已刷新代理并重启。栈健康检查及两个池的注册／认证配置接口通过，最终只读审计无冲突和异常。独立测试服务器须对自己的数据库先审计再迁移，本轮没有连接或修改远程服务器。
