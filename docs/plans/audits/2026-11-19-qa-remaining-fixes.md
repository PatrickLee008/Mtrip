## 已修复

| 问题 | 修复后的行为 |
|---|---|
| 分享链接指向旧域名，打开后不读取推荐码 | 默认分享当前 H5 域名 `/r/推荐码`；打开后进入手机号注册，推荐码贯穿 OTP 与现有无短信支持分支 |
| 邀请注册容易丢码或跳过绑定 | 邀请码预填、只读、不可静默跳过；普通注册保留手填/跳过。邀请入口使用手机号注册；普通注册的社交入口保留 |
| 邀请入口的登录与完成导航不正确 | 已有用户可去登录，成功认证清除邀请；新注册完成返回首页并清理邀请 URL，已有账号不会重新绑定 |
| UTC 截止时间被当成手机本地时间 | 完整/关怀模式共用 UTC 解析，兼容明确时区，拒绝非法日期；Trip 使用待支付子单中最早的有效截止时间 |
| 倒计时归零只查询一次，长期停在0秒 | 归零后每3秒查询，直到服务端确认已支付或已取消/过期；失效后禁止再次发起付款 |
| Trip 的真实付款结果未替换旧失败提示，付款响应丢失后仍报失败 | 重读服务端的父单支付状态或单订单状态，确认成功后清理旧失败原因；重新付款使用原订单，不创建新订单 |
| “查看预订”打开通用列表/旧详情 | 有 Trip 编号打开 TripDetail；有单订单编号打开 BookingDetail，完整/关怀模式一致 |

代码集中在 `referralInvitation.ts`、注册/导航入口、`time.ts`、`useBookingResult.ts` 与两种结果页。本轮没有修改后端、数据库、生产业务数据或真实短信配置；上一轮返利修复仍保留在工作区。
