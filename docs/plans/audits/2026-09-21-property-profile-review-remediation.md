# 物业资料审核流程整改审计

日期：2026-09-21

## 目标与范围

本次解决物业 KYC 审核完成后，运营人员找不到物业资料审核入口、商户端状态含义混杂的问题。整改只涉及管理后台、商户 Web、merchant-service、菜单迁移和回归测试；未修改 `merchant-app` 与 `client-app`。

KYC、物业资料、房型审核和发布保持四条独立门禁。本次不自动创建资料版本，不自动提交，也不自动批准。

## 最终流程

1. 商户新增物业并提交物业 KYC 文件。
2. 管理员在“商户管理 → 商户文档”逐份审核物业 KYC。
3. 最后一份必需文件通过后，后台提示下一步由商户完善并提交物业资料。
4. 商户在酒店资料页保存草稿并提交，状态从“待完善物业资料”进入“物业资料审核中”。
5. 管理员在“商户管理 → 物业资料审核”查看版本差异和媒体，执行通过或驳回。
6. 首次通过后物业进入未发布链路；驳回时商户看到原因并修改重交。
7. 已有批准版本的物业提交新修订时，旧版本继续生效，直到新版本通过后才替换。
8. 物业资料通过仍不能代替房型审核；满足已批准房型及发布、经营、展示门禁后才对用户端可见。

## 实现结果

- 独立页面：`/merchant/property-review`，组件 `merchant/property-review/index`。
- 查看权限：`merchant:property:content-list`；审批权限：`merchant:property:content-audit`。
- 兼容入口：“商品审核 → 物业资料审核”保留跳转，不再维护第二套审核 UI。
- 管理列表返回标准分页字段和额外 `stats`；统计与列表均按管理员站点隔离。
- 商户列表读取最新资料版本状态，并区分首次草稿、待审和驳回。
- KYC 文档审核返回物业聚合状态和下一步标识，后台只在全部通过时显示资料完善提示。
- 迁移 `V20260921130000__add-property-profile-review-menu.sql` 新增页面菜单，将既有审批按钮挂到新页面，并保留既有角色授权。
