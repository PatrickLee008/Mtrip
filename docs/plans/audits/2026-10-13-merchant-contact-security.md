## 用户操作入口

- Merchant Web 登录页新增“领取激活凭证”，路径 `/claim-credentials`。填写申请号与原注册 E.164 手机号，仅返回通用发码结果；正确手机 OTP 后才能给注册邮箱发 OTP，正确邮箱 OTP 后才投递凭证。申请号或未验证邮箱本身不能授权领取。
- Merchant Web `设置与安全` 增加“登录联系方式”。分别显示邮箱／手机号的真实验证状态，未验证渠道可补验。补验完成只更新对应渠道，之后可用于该渠道 OTP + Authenticator 登录。
- 设置页换绑：Authenticator → 现有真实已验证渠道 OTP → 新联系方式 OTP → 原子更新申请和账号 → 历史旧身份释放审计 → 所有会话与未用挑战失效 → 重新登录。
- 管理后台 `所有商户 → 详情 → 账号安全 → 核验后更正登录联系方式` 仅超级管理员可操作，权限 `merchant:list:contacts`。人工审核后填写完整手机号、邮箱和至少 10 字的核验依据；未变更的渠道保留证明，变更的渠道清除证明。待激活账号旧凭证过期，须重新领取。失去全部渠道时必须先由管理员完成人工核验，不提供“一键真实已验证”。
- 入驻详情显示真实／测试／管理员证明来源、时间、脱敏联系方式；待领取、待投递、服务商已受理与待激活分开显示。失败记录可重试，已受理记录不因管理员刷新重复发送。商户经新一轮双 OTP 可重新签发凭证。

## SMSPoh 内容短信启用

官方内容接口：[RESTful SMS API](https://smspoh.com/v3/developers/restful-sms-api-specification)。使用 `POST https://v3.smspoh.com/api/rest/send`，JSON 字段 `to/from/message/clientReference`，`Authorization: Bearer base64(APIKey:APISecret)`。这与 `/api/otp/request`、`/api/otp/verify` 分离。凭证和 API 密钥不进入查询 URL；响应可能回显短信全文，客户端只保留消息 ID 和受理结果，错误仅保存通用错误码。

部署变量 `MTRIP_MERCHANT_CREDENTIAL_SMS_CHANNEL_ID=0` 默认关闭内容直投。经服务商确认 V3 内容接口权限、Sender ID／模板和覆盖国家，并由受控收件人验收后，设置为对应的启用 SMSPoh 渠道 ID。该渠道必须属于当前站点或全局站点 0。修改 Compose 环境变量需重建对应服务容器，重启进程不能注入新的环境变量。不能仅凭后台 OTP 发送测试成功打开此变量。本轮未调用任何真实发信接口，也未修改现有渠道凭证。

未启用或内容投递失败时，账号和批准结果保留；商户通过领取入口完成手机和邮箱的真实 OTP 后发邮件。管理员代录不能直接给未验证邮箱发送账号秘密。测试模式仍由既有后台运行时开关及部署门禁控制，测试凭证展示仅超级管理员可用，固定 `000000` 不写真实验证时间。
