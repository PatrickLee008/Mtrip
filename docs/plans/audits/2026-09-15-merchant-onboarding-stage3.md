# 商户入驻审批整改阶段 3 执行报告

日期：2026-09-15  
范围：商户 KYC、首批物业 KYC、电子签署和管理端审核；未修改 `merchant-app/**`、`client-app/**`。

## 交付结果

- 基础注册批准时冻结商户主体模板和各首批物业模板，并按 `application_id + scope_type + application_business_id` 生成独立文件清单；新记录不再写 `biz_unit`。
- 公开 KYC 接口已补齐详情、双范围要求、文件上传、条款全文、滚动确认、电子签署和提交。注册 Token 同时绑定站点、申请 ID、手机号 HMAC 和邮箱 HMAC，跨申请与跨范围请求均被拒绝。
- 条款阅读凭据绑定条款 ID、版本、正文 SHA-256 和申请，30 分钟内有效；签名保存文件 SHA-256、签署人、角色、阅读/签署时间、IP 和 User-Agent。新条款生效后旧签名保留审计记录，但最终批准门禁要求重新签署。
- 文档审核支持逐文件通过或驳回，并使用当前文件版本做并发校验。驳回只把所属商户或首批物业范围置为需补正；其他已通过范围保持有效。替换文件递增版本并保留原文件快照、审核事件和驳回原因。
- 管理端文档库显示商户主体或首批物业范围、申请号和物业名称，审核/下载按入驻 KYC 权限及站点范围控制；入驻详情展示当前条款、各范围状态、文件状态、原因和最终批准门禁。
- `V20260915180000__complete-onboarding-kyc.sql` 幂等发布平台条款，并为已进入 KYC 的新状态申请冻结模板、补齐双范围文件占位。

## 状态与门禁

- 商户主体和每家首批物业独立执行 `draft -> submitted -> under_review -> approved/resubmit_required`。
- KYC 提交要求当前条款已签署，且所有本次可编辑范围的必需文件已上传；已通过范围不会在其他范围重交时回退。
- `finalApproval.ready` 同时校验基础注册、商户主体 KYC、全部首批物业 KYC、必需文件有效性和当前条款签署。管理端已展示该门禁；阶段 4 的最终批准按钮和创建事务必须直接复用此服务端校验。
