## 5. 代码基线结论

| 项目 | 当前实现 | 结论 |
|---|---|---|
| 注册 OTP | 有渠道配置、发送、校验、过期、冷却和尝试限制 | 部分满足；只验证所选渠道，未保存两种联系信息 |
| OTP 后草稿 | OTP 返回临时令牌，App 随后保存并立即提交 | 不满足“OTP 成功立即创建可恢复草稿” |
| 注册业务 | 后端强制把 `businessType` 写为空 | 不满足酒店首批物业类型识别 |
| 基础注册审批 | `Onboarding` 有队列和审批操作 | 职责不一致；当前批准会过早创建正式商户 |
| 自助 KYC 提交 | 路由指向 `ApplicationController::kycSubmit()` | P0 阻断；控制器没有该方法 |
| KYC 文档归属 | 申请级空 `biz_unit` 与业务 ID 级并存 | P0 不一致；最终门禁可能看不到自助上传文档 |
| 电子签署 | 没有完整条款版本、签名、签署人、时间戳模型 | 缺失 |
| 最终批准 | 有验证审核、访问码和账号创建能力 | 部分满足；访问码格式、首批多物业事务和真实投递不符合目标 |
| 新增物业 KYC | 已有 `scope_type=property/property_id`、独立审核和版本 | 基础能力已存在，后续避免重复实现 |
| 酒店内容/房型版本 | 已有独立审核、旧批准版本保留和发布门禁 | 基础能力已存在，需并入最终端到端验收 |
| 用户端酒店 API | 已有 `/api/v1/app/hotels/*` | 基础能力已存在；普通搜索当前仍从排名发布快照取候选，需解耦 |

## 7. 阶段 0 判断

阶段 0 可以通过，下一阶段具备明确输入，但不代表 PRD 模块 1 已通过验收。阶段 1 开始前固定采用以下口径：

1. 商户、注册业务和物业按实体契约分层。
2. 注册、商户 KYC、账号三个状态独立。
3. 商户级文档不再按 `biz_unit` 复制；首批物业文档归属申请业务，运行期转换为 `property_id`。
4. 基础注册批准只开放 KYC；最终批准才创建正式商户、主账号、首批物业和访问码。
5. 两个 App 冻结，后端先按接口契约实现，App 接入另立阶段。

## 8. 审计限制

- 本阶段没有创建隔离申请或执行真实审批，因此没有声称当前流程端到端可用。
- 没有可复用的登录态浏览器会话，未执行后台页面操作验证。
- 当前运行库样本量很小；后续迁移必须在隔离库覆盖单物业、多首批物业、部分驳回、重交和事务回滚场景。
