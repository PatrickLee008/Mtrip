## 需求与设计

- 原型四段式 600px 抽屉：佣金方案及自定义比例、按佣金计算的交易手续费率、到店支付开关、未到店费用开关及房费预收比例、生效日期/时间和必填原因；固定底栏取消/保存。独立保留账号安全与月度表现，详情新增当前商业条款摘要和配置历史。
- 佣金方案沿用 vip/premium/standard，不根据方案自动覆盖自定义费率。费率使用最多两位小数，佣金及交易手续费 0–100%，商户预收 0–30%；到店支付关闭时不允许启用商户预收，未到店费关闭时预收比例必须为 0。到店支付时佣金加商户预收不得超过房费。
- 实时预览以 100,000 MMK 示例房费计算，明确列出佣金、佣金金额上的交易手续费、商户预收、合并预付款和到店余款。手续费独立展示，不能擅自加入 PRD 定义的“佣金 + 商户预收”预付款。关闭到店支付时不展示误导性的到店预付示例。
- 配置保存为不可覆盖的版本记录，包含站点、商户、全部条款、生效 UTC 时间、操作者及原因。保存时锁定商户并校验预期版本，防止并发覆盖；请求编号支持安全重试。按生效时间解析当前条款，未来版本不提前影响当前值；历史保留计划、费率和关闭状态。
- 历史商户以已有佣金方案/费率作为未配置基线，新增开关默认关闭、交易手续费为 0，不自动给现有商户开放到店支付。详情/列表使用生效版本的商户费率，旧佣金写入口不得绕过原因和版本历史。
- 订单在首次确认时冻结所适用的商业条款，后续重试及配置变更不得覆盖已确认快照；单笔和 Trip 子订单使用同一入口，消费者接口不泄露内部商务快照。现有已确认订单不批量重算。
- 用户已明确确认：本轮实现后台完整配置、配置历史和条款快照，App 到店支付继续暂不开放。现有消费者收款、退款、到店余款及财务结算流程不在本轮改动；订单快照为条款留存，不代表新支付能力已经开放。

## 实施步骤与验收

API 契约：`GET/POST /admin/merchant/commercial-settings`，读取返回 `{merchant_id,latest_version,current,next}`；`GET /admin/merchant/commercial-settings/history` 返回标准分页。写入包含 `id/expectedVersion/requestId`、六项商业配置、带时区的 `effectiveAt` 和必填 `reason`。Terms 使用 snake_case，开关为布尔值，百分比为十进制字符串；版本 0 表示未保存新配置的原商户基线。

1. 金额规则 → `backend/shared/src/Merchant/CommercialTerms.php` 与 `backend/shared/tests/cases/CommercialTermsTest.php`。先写失败测试，验证百分比基数、0/30%边界、非法输入、联动与精度，随后实现整分/基点计算。
2. 存储与服务 → 新增 `database/migrations/V20261117100000__merchant-commercial-settings.sql`；新增商户配置版本表、商户配置并发版本、订单条款快照列。shared 读取类供商户及订单服务共用；merchant-service 服务执行原子保存和历史读取。验证幂等迁移、生效时间、请求重试、并发冲突、站点和权限隔离。
3. API 与兼容 → 新增 `/admin/merchant/commercial-settings` GET/POST 与 `/commercial-settings/history` GET，复用 `merchant:list:list` / `merchant:list:edit` 权限；替换旧佣金入口的直接写入，防止遗漏原因/历史。列表和详情只读映射当前配置，不改变结算周期。
4. 后台展示 → 新增 `admin-web/src/components/merchant/CommercialSettingsDrawer.vue`，替换所有商户详情旧佣金弹窗；接入真实保存、当前/待生效版本和历史。新增中英词条及组件交互测试，覆盖非法比例、开关联动、未填原因/日期、重复提交与保存后刷新。
5. 确认快照 → `order-service/Service/PaymentResultHandler.php` 首次确认/超时到账恢复共用快照读取；保留既有付款方式，旧订单幂等确认不回填新条款。验收单笔及 Trip 子单、未来生效与已确认订单不变。
6. 集成与交付 → 专用空数据库克隆结构测试，不使用真实商户保存；执行迁移校验、服务端/组件专项与项目质量基线。检查原型一致性、中英文、375px及弹窗层级；本机上线前备份双库及后台资源，仅通过标准迁移工具执行新迁移。更新模块 15、README 进度及 HANDOFF，列明实际支付开放边界。
