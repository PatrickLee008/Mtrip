# M12 第一批任务清单与验收矩阵

> 日期：2026-08-27。状态：S1及S2代码与核心集成测试已完成，最新证据和未测项见03-s2-delivery.md。
> 依据：阶段0技术设计00-design.md；PRD模块12；D1～D8已确认决策。
> 用户已批准设计及G2/G3/G4；酒店优先，餐厅实现延期。以下为原计划矩阵，实际结果以交付报告为准，不将计划用例等同于已通过。

## 1. 第一批目标与边界

目标：商户状态管理真正控制登录与新订单；临时停用、黑名单解除和历史订单的行为一致、可审计。

本批不做：2FA完整注册/验证、真实模拟登录、目录视觉重构、真实排名、餐厅交易系统、外部通知服务商接入。只补这些后续功能需要的最小状态/审计基础。

共用门票代码不重分类、不改订单算法；修改共用函数必须增加门票回归。模拟登录旧入口在其安全闭环完成前不作为可验收能力。

## 5. 测试数据和执行约束

- 目前开发库无商品/订单，因此不能用现有页面截图声称下单验收通过。
- 后续创建专用测试库或明确标记的测试站点，覆盖：两个站点、一个集团、正常/停用/拉黑商户、酒店与餐厅门店、多个登录账号、酒店SKU、单笔及Trip订单。
- 测试数据创建脚本记录全部ID；清理只按这批ID执行，禁止宽泛DELETE、DROP现有库或docker down -v。
- 真实服务商通知和生产支付不参与本轮测试；不得用模拟成功掩盖延期能力。
- 需要第三方依赖、影响其他业务或无法安全回退时先说明影响，不扩大范围。
- 并发、到期和时间测试使用可控制时钟/隔离任务执行，防止修改全局系统时间。
- 构建和类型检查不能替代端到端业务验收；失败或未执行必须如实列出。
