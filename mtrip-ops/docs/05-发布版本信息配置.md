# 发布版本信息配置

## 当前能直接显示什么

Mtrip Ops 可以从 Docker 获取以下运行态信息:

- 容器状态:running / stopped / exited / missing / unknown
- 启动时间:来自 `docker inspect .State.StartedAt`
- 运行时长:由启动时间实时计算
- 镜像名:来自 `docker inspect .Config.Image`
- CPU/内存/网络/Block IO/PIDs:来自 `docker stats --no-stream`

前提是运行 Mtrip Ops 的用户有 Docker 只读访问能力。如果没有权限,页面会显示 `unknown` 或 `not available`,不会伪装成 missing。

## 当前不能凭空显示什么

发布时间、业务版本号、发布说明不是 Docker/Compose 默认提供的业务语义。当前 Mtrip 的 `deploy/docker-compose.yml` 没有统一写入这些元数据,所以 Ops 会显示“未配置”。

需要通过以下任一方式提供。

## 方式一: deploy/release.json(推荐第一阶段)

在 Mtrip 主项目生成 `deploy/release.json`,Ops 默认会读取它:

```json
{
  "global": {
    "version": "2026.09.02-001",
    "publishedAt": "2026-09-02T18:30:00+08:00",
    "gitSha": "abcdef1234567890",
    "notes": "订单与 APP 孪生池发布"
  },
  "services": {
    "user-service": {
      "version": "2026.09.02-user-001",
      "publishedAt": "2026-09-02T18:31:00+08:00",
      "gitSha": "abcdef1234567890",
      "notes": "用户登录与常旅客修复"
    },
    "user-service-app": {
      "version": "2026.09.02-user-001",
      "publishedAt": "2026-09-02T18:34:00+08:00",
      "gitSha": "abcdef1234567890",
      "notes": "同步 APP 用户服务"
    }
  }
}
```

优点:

- 不需要改 Dockerfile。
- 适合由 `scripts/auto-deploy.sh` 在发布成功后生成或追加。
- 能记录单服务发布说明。

建议后续在 `auto-deploy.sh` 每次成功后写入:

- global.version
- global.publishedAt
- global.gitSha
- services.<service>.version
- services.<service>.publishedAt
- services.<service>.notes

## 方式二:Docker labels

在 compose 服务里增加 labels:

```yaml
services:
  user-service:
    labels:
      mtrip.release.version: "${MTRIP_RELEASE_VERSION:-dev}"
      mtrip.release.time: "${MTRIP_RELEASE_TIME:-}"
      mtrip.release.git_sha: "${MTRIP_RELEASE_GIT_SHA:-}"
      mtrip.release.notes: "${MTRIP_RELEASE_NOTES:-}"
      org.opencontainers.image.version: "${MTRIP_RELEASE_VERSION:-dev}"
      org.opencontainers.image.revision: "${MTRIP_RELEASE_GIT_SHA:-}"
      org.opencontainers.image.created: "${MTRIP_RELEASE_TIME:-}"
```

优点:

- 元数据跟随容器。
- `docker inspect` 可直接读取。

注意:

- label 在容器创建时固定,改 `.env` 后必须 `mtrip.sh start` 或 build 重建容器才更新。
- 单服务不同发布说明用全局 `.env` 不方便,更适合配合 release.json。

## 方式三:环境变量

在 compose 环境变量里写入:

```yaml
environment:
  MTRIP_RELEASE_VERSION: "${MTRIP_RELEASE_VERSION:-dev}"
  MTRIP_RELEASE_TIME: "${MTRIP_RELEASE_TIME:-}"
  MTRIP_RELEASE_GIT_SHA: "${MTRIP_RELEASE_GIT_SHA:-}"
  MTRIP_RELEASE_NOTES: "${MTRIP_RELEASE_NOTES:-}"
```

Ops 也会从 `docker inspect .Config.Env` 读取这些值。

## Docker 权限配置

如果服务页显示 Docker unreadable,说明运行 Ops 的用户没有权限读取 Docker API。

开发环境可选:

```bash
sudo usermod -aG docker <运行用户>
# 重新登录后生效
```

生产环境更推荐:

- 使用 `docker-socket-proxy` 暴露只读 API。
- 或把 Docker 命令放入本地 runner,Web 进程只提交白名单任务。
- 不建议把 `/var/run/docker.sock` 直接暴露给公网可访问的 Web 服务。

## 建议路线

第一阶段使用 `deploy/release.json` 记录发布语义,Ops 展示它。
第二阶段给 Docker 镜像/容器加 OCI labels,让镜像本身也携带版本。
第三阶段把 `auto-deploy.sh` 接入 release.json 自动写入与发布审计。
