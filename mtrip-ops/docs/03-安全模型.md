# Mtrip Ops 安全模型

## 默认策略

Mtrip Ops 默认只读:

- `host=127.0.0.1`
- `enableActions=false`
- 不直接暴露 Docker socket
- 不内置业务库写权限

生产环境必须放在内网、VPN、堡垒机或 SSH tunnel 后面,不要公网裸露。

## 动作分级

| 级别 | 示例 | 默认 |
|---|---|---|
| 只读 | 查看 health、日志、容器状态 | 允许 |
| 低风险动作 | `auto-deploy.sh --dry-run`、`mtrip.sh health` | 需 `enableActions=true` |
| 中风险动作 | 重启单服务、DB backup | 后续加二次确认 |
| 高风险动作 | 正式部署、DB apply、clean/down -v | 后续加审批/双人确认 |

## 命令白名单

所有子进程执行必须满足:

- 使用 `execFile`,不用 shell 拼接。
- 命令名和参数由服务端白名单生成。
- 页面请求只传动作 ID,不传任意命令。
- stdout/stderr 和退出码写审计。

## 审计字段

后续发布记录至少包含:

- 操作人
- 来源 IP
- 动作类型
- 目标服务
- before/after git SHA
- 命令参数
- 开始/结束时间
- 退出码
- stdout/stderr 摘要

## Docker 权限

直接挂载 `/var/run/docker.sock` 等同宿主 root 权限。后续如需 Docker Engine API,优先:

1. 使用 docker-socket-proxy 限制 API 能力。
2. 将重启/部署动作放到本地 runner,Web 只发白名单任务。
3. Web 进程用低权限用户运行。
