# 成熟软件调研

## Prometheus + Alertmanager

优点:

- 指标采集、时序存储、告警规则非常成熟。
- 适合服务延迟、QPS、错误率、资源负载等数值指标。

不足:

- 不负责发布管理。
- 对日志需要另接 Loki/ELK。
- 对当前阶段偏重。

参考: https://prometheus.io/docs/introduction/overview/

## Grafana + Loki

优点:

- Grafana 仪表盘生态成熟。
- Loki 成本低,适合日志聚合。

不足:

- 多组件部署。
- 仍需自研 Mtrip 发布与业务态势。

参考: https://grafana.com/docs/loki/latest/get-started/overview/

## Netdata

优点:

- 主机、容器、系统负载实时监控开箱即用。
- 部署轻,适合补齐底层资源视角。

不足:

- 不理解 Mtrip 的 APP 孪生池、发布脚本和业务指标。

参考: https://learn.netdata.cloud/docs/getting-started/

## Uptime Kuma

优点:

- HTTP/TCP/Ping/Docker 可用性监控轻量好用。
- 状态页和通知体验好。

不足:

- 不做深度日志、业务统计和发布管控。

参考: https://github.com/louislam/uptime-kuma

## Zabbix

优点:

- 企业级全功能监控,适合大规模主机和应用。

不足:

- 部署配置重,不适合作为当前轻量独立运维台第一版。

参考: https://www.zabbix.com/documentation/current/en/manual/introduction

## Portainer / Cockpit

优点:

- 容器/服务器管理成熟。

不足:

- 权限边界大,暴露 Docker 管理能力风险高。
- 缺少 Mtrip 业务和发布语义。

参考: https://docs.portainer.io/ 与 https://cockpit-project.org/
